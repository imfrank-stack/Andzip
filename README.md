# Andzip

Bandizip 风格的 Windows 压缩工具。**界面是 C#（.NET 10 + Avalonia，控件全部用代码构建，没有 XAML），压缩/解压内核是 C/C++**（原样 vendor 的 7-Zip，外面包一层只有 43 个函数的扁平 C ABI）。

一个二进制两种用法：免安装的 `dist/Andzip-v<版本>-win-x64.exe`，和双击就装的
`dist/Andzip-Setup-v<版本>-win-x64.exe`（桌面上那枚图标带透明通道）。各约 21 MB。

---

## 一、为什么做这个

- **用着顺手**。照 Bandizip 的交互做：首页双栏、树 + 详情列表、右键直接解压、进度条跑完自己消失。
  很多人已经习惯这个形状，照着做不需要重新学。
- **干净**。免安装单文件，或者装到 `%LOCALAPPDATA%`（默认那条路只写 `HKCU`，不要管理员权限；
  2.1.0 起也可以选「为所有用户」，那一条走 `Program Files` + `HKLM`，弹一次系统确认；
  3.2.0 起一台机器只留一份）。改默认程序只动你明确勾选过的格式，**并且先把原来的默认值记下来**，
  取消勾选时还回去；不碰别的软件的 ProgID，**不伪造 Windows 的默认应用保护哈希**
  （那是绕过系统安全机制，走不得）。卸载只收回它自己做过的那几样。
- **能力来自真正的引擎，而不是自己造解码器**。7-Zip 的格式覆盖面是事实标准，直接复用；
  本项目的工作在**接口层与产品层**：把 284 个编译单元的 C++ 收成一个稳定的 C ABI，
  再在上面长出界面、路径安全、重名策略、分卷、进度上报。
- **一条能被别人复用的工程记录**：怎么 vendor、扁平 C ABI 怎么设计、同一台 Windows 主机上
  怎么交叉编译 Windows / Linux x86_64 / Linux aarch64、单文件裁剪哪些开关真有效（哪些是白费功夫）。

**它不打算做的事**：成为 7-Zip 的替代品（功能还差得远）、做全平台原生 UI、
任何形式的"绕过系统安全机制来抢占默认程序"。

## 二、现状

| 项 | |
|---|---|
| 主要平台 | **Windows x64** —— 构建、测试、运行、打包都在本机验证过 |
| 格式能力 | 引擎报告 **64 种可读 / 11 种可写**（应用里给 7 种：ZIP、7Z、TAR、TGZ、GZ、BZ2、XZ；7Z 另有 11 种压缩方法可选） |
| 单文件绿色版 | **20.84 MB**（21,856,084 字节，5.3.0 实测）；带上五个扩展编码器之后比 2.1.0 重 1.6 MB |
| 正常安装 | 同一个 exe 改名即安装器：分页向导（欢迎 → 为哪位用户安装 → 选安装位置，实时报所需/可用空间 → 进度 → 完成）。桌面与开始菜单快捷方式、开始菜单里有「卸载 Andzip」、安装目录里有能双击的 `uninstall.bat`、控制面板也能卸。「仅为我自己」全程不弹 UAC；「为所有用户」装与卸各弹一次。「一台机器只留一份」：检测到另一作用域里那一份会说清它是谁、在哪，并默认勾着"装之前先卸掉它"，不勾就不给下一步。页脚紧跟正文；完成页比中间那几页矮——窗口高度为一条真机 bug 立过"只长不缩"的规矩，那条规矩给最后一页开了例外 |
| 测试 | **1599** 项断言全绿（原生 649 + Core 533 + 界面 225 + P/Invoke 外壳 192），另外每次打包对**产物自己**再跑 25 项安装往返自检 |
| CI | GitHub Actions，Windows 跑与本地完全同一份门禁脚本 `ci.ps1` |
| Linux / macOS | 内核能交叉编译、CI 有真机作业；**界面从未在这些平台运行过** |

打开、浏览、压缩、解压、文件关联、右键菜单、查找、密码恢复、**包内编辑（增删改名 / 归档注释 /
剪贴板）**、**图像预览**（4.6.0）、**CRC 校验和（十一种算法，4.7.0）**都可用；
**非图片的内容预览（文本、PDF…）还没有**。读完下面两张清单再决定要不要用。

### 已完成

#### 界面与主题

- **一套有文档的界面风格**（1.4.0）：色板、圆角、间距、字号、组件、图标全部收进
  `docs/界面设计规范.md` 与 `Design.cs` / `Chrome.cs` / `Icons.cs`，界面代码里**没有一个字面色值**
  （有测试扫源码把关）。按钮、输入框、下拉、卡片是圆角的，每个可点的元素悬停都有反馈。
- **无边框的圆角窗口**（1.7.0）：主框体自己就是那张圆角面板（大圆角 + 多层外阴影，**四周**都有影，
  包括顶边），系统标题栏换成自绘的那一条。顶栏只有一行
  `图标 + 文件 编辑 查找 选项 视图 工具 帮助 …— □ ✕`（2.4.0）；版本号住在面板右下角（3.1.0 起），
  截图因此自带身份，而窗口自己的 `Title` 照旧带引擎信息给任务栏与读屏器。
  用的是"扩展客户端区"而不是关掉系统装饰，所以贴边缩放、Win+方向键分屏、任务栏让位都还在，
  最大化时圆角与边距自动收掉。圆角外那一圈**每一扇窗口都是透明的**（2.4.1 起由 `Chromeless()` 保证）。
  顶部与内容在同一张表面上，中间只有一根 1px 的线——一屏切成四块白板那种"割裂感"是被明确否掉的。
- **悬停会浮起，弹出框没有直角**（1.8.0）：可点的控件被指针扫到时是一枚"浅灰 + 圆角 + 外阴影"的药丸；
  子菜单、下拉列表、提示气泡同样圆润带影；关闭按钮的悬停是一颗淡红芯片，不是整块实心红。
  两处明确的例外：菜单栏那一排（2.5.1，同时压掉主题自带的那圈蓝描边）与工具栏那张卡片（3.3.0）
  只换一块**平的淡色填充**——两层"浮"读起来是脏不是层次。每一颗 `new MenuItem`
  由一条扫源码的断言要求接上同一个包装。
- **按下那一档归我们画**（1.8.7 / 1.8.8 / 1.9.0）：主题在"按住"这一刻会往模板面皮上涂一整块深灰，
  浅底上读起来像按坏了。现在三档是 `静止 = 表面白 → 悬停 = 压一档 → 按住 = 再压一档`
  （真机量的 `#FFFFFF` / `#F6F8FA` / `#E9EDF1`），连下拉框右边那格箭头也在内，
  并且有测试盯着"漏接一颗按钮"这种事。
- **夜间模式**（`设置 → 查看 → 界面主题`，3.8.0 起「视图」菜单最后还有一条**「深色模式」**直接切）：
  跟随系统 / 浅色 / 深色，换完立即生效不用重启。深色不是把浅色取反：主按钮的蓝要压深（它是白字的底），
  选中行的蓝要压成深蓝（它是浅字的底），语义色换成粉彩，底不用纯黑——两套调色板与对比度写在规范 §十。
  3.9.0 起画刷**全进程只有一份**，换档改的是它们自己的颜色，所以已经开着的窗口与正看着的包
  当场跟着走；只有阴影（结构体，没有实例可改）与位图图标要靠重做，主窗口本来就重做那两处。
  菜单最后一条是"点一下就换，再点一下回到进深色之前那一档"，不是三态循环——那种设计猜不到下一次到哪。
  **深色模式那个下拉从 1.5.0 就接得上线，可它住在九页设置的第五页，用户找不到；
  缺的从来不是功能，是入口**（同一条教训在"没有卸载入口"那件事上先犯过一次）。
- **换语言当场生效，不用重启**（5.1.0）：语言目录广播一次，开着的窗口各自重做文字。
  外壳（菜单 / 工具栏 / 首页 / 设置窗口整扇）整条重做，**正看着的压缩包视图就地改字**——
  换一种语言不该把人从正在看的文件夹里扔回根目录，连展开、列宽一起丢。
  唯一做不到的那半写在语言页上：资源管理器里那几条右键菜单的名字存在注册表里，不是界面文字，
  要等下次启动自愈或在那几页再点一次「立即应用」。
- **首页顶栏是一张浮起的圆角卡片**（3.3.0）：整条工具栏坐在面板上，圆角 + 四周那一圈淡影，
  与面板之间不再压发丝线。九颗按钮平均铺满整条卡片（3.5.0，`UniformGrid`），标签统一两个字（3.1.0）：
  **打开 / 解压 / 新建 / 添加 / 删除 / 测试 / CRC / 查看 / 切换**——解释"这一格是什么"的活交给图标，
  字只负责确认。九枚图标读的是 `assets/svg/*.svg` 设计稿（2.6.0，运行时从内嵌资源解析成几何）：
  抄一份路径进代码就等于造出第二份会撒谎的真相。稿子里那三个字面色不照抄，
  映射成 `Icon.Glyph` / `Icon.Accent` 两个令牌，那圈"挖空"映射成卡片底色。
  最后一颗「切换」打开**设置 → 语言**。九颗现在没有一颗是死占位。
- **工具栏有三档**（4.4.0，`视图 → 工具栏`）：**大**（图标 + 文字）、**小**（只画图标，整张卡片
  从量的 90 DIP 降到 40 DIP；文字没丢，挪进九条悬停提示，读屏拿到的名字也一起补上）、
  **隐藏**。三档是**一个值**而不是"显示开关 + 大小开关"两个，否则就得回答"隐藏着的工具栏是大的
  还是小的"这种没人问的问题；「设置 → 查看」里那个「显示工具栏」开关因此整行删掉。
  换档会重做整条工具栏，所以重做之后一定重算一遍灰与亮（4.4.1）——
  曾经切完档就得到两颗**亮着、点下去什么也不发生**的「添加」「删除」。
  参考图里的「旧样式」与「工具栏按钮设置」没做，理由见 CHANGELOG。
- **程序图标**（1.6.0）：蓝底圆角方块 + 两片白纸 + 一条拉链 + 琥珀色拉头，由 `assets/make_icon.py`
  画出来，七档尺寸（16 / 24 / 32 / 48 / 64 / 128 / 256）各自单独构图——16px 上拉链齿会糊成一团，
  那一档只留三样东西；小尺寸存无压缩位图（老组件读 PNG 的 16px 会读成空白）。
- **图标配色**（2.5.0，`设置 → 查看 → 图标配色`）：同一张图在应用里重新画了一遍，五档渐变、
  四个方向、八套预设、两种字形（溢出裁切 / 镂空负形），改一处立刻重画预览。
  「设为桌面图标」把生成的那张落到 `%APPDATA%\Andzip\Andzip.ico`，然后换四处：正在跑的窗口与任务栏、
  桌面与开始菜单的快捷方式（只改图标字段）、已登记的格式图标 `DefaultIcon`，最后通知 shell 重读缓存。
  **只动已经存在的项，`UserChoice` 一个字都不碰**；改了几处就报几处，绿色版没有快捷方式就明说没有。
  「恢复默认」指回 exe 里那张出厂图。这一节的用途是"让它成为这台机器上的图标"，
  抠图另存的两颗导出按钮 4.9.0 删了。**这张图是算出来的，不是任何生成式素材。**
- **两栏之间那根线拖得动**（1.8.9）：树与详情列表之间是 1px 发丝线，底下压着 8px 命中带，
  按住可调左栏宽度（首页与开包后同一处）。以前它画得对但拖不动。

#### 主窗口与浏览

- **鼠标离开菜单那一块就自动合上**（3.2.0）：Avalonia 的菜单本来点开就一直挂着，而这一排住在自绘
  标题栏里，指针移走了下拉还压在工具栏上，读起来像界面卡住。判据是**位置**不是"哪一次进出事件"
  （从那一项挪进下拉本来就会先触发一次 `Exited`，按事件关会让菜单点不动），门槛是距离（48 DIP，3.5.0），
  而"整条菜单栏"与**每一层开着的弹窗**都算在这一带里面——只数得到第一层的时候，
  二级菜单「视图 → 列设置」根本点不到（4.6.2）。键盘（Alt）开出来的那种不受影响。
- **浏览压缩包**：树形目录 + 11 列详情列表（列宽可拖拽、长文字不遮挡）、图标视图带缩略图、
  状态栏汇总；能作为单个归档打开 `archive.7z.001` 这类多卷包。子文件夹**默认收着**（根节点展开），
  要一次全摊开在「设置 → 查看」里勾。
- **哪些列要显示**（`视图 → 列设置`，4.1.0）：十行带勾的子菜单，点一下**当场**少一列，
  树、当前所在的文件夹、展开状态、选中项原地不动。名称列与末尾那条吃剩余宽度的填充列不给勾。
  排序与列宽**按列自己的身份记**，勾掉一列不会把后面每一列整体错位一格。
  选择存在 `settings.ini` 的 `hidden_columns`，跨重启；存的是"关掉了哪些"而不是"显示着哪些"，
  所以以后新增一列天然就是显示的，不用给老设置补一次迁移。首页上这一项是灰的（没有表可改）。
- **在包里找东西**（`查找 → 文件查找`，`Ctrl+F`）：非模态的一张小窗，输入即过滤，
  匹配的是**完整路径**、不分大小写，底下写「找到 3 项（包里共 6 项）」，结果列的也是完整路径。
  「定位」（或输入框里那下回车）把主列表跳到它所在的那一层、选中那一行、滚到位，
  左边的树跟着走过去，窗口不关——查找的天性是"搜一下、看一眼、再改个词"。
  参考软件那一排的「删除」「解压」两颗按钮这里没有：这一扇只负责找到并跳过去。
- **最近的文件**（`文件 → 最近的文件`）：最多 10 条，最新在前，点一下就在当前窗口里打开；
  只有**打开成功**的包才记账（失败的包、被取消的口令不算），文件被删掉后那条记录自己消失；
  跨重启保存，底下有「清除最近使用的文件记录」。
- **对压缩包本身的操作**（`文件` 菜单）：**另存为**（原样复制一份，不重压）、
  **删除压缩文件**（`Ctrl+Del`，真的进回收站，删之前先问）、
  **永久删除压缩文件**（`Shift+Ctrl+Del`，确认文案写清楚它不给反悔的机会）、
  **打开压缩文件位置**（在资源管理器里选中这个包）。
  这四条只在正开着包时可点——一条能点、点了什么也不发生的「删除压缩文件」比灰着危险得多。
- **拖拽进主窗口**：拖**一个压缩包**进来 → 在这个窗口里打开它；拖**普通文件 / 文件夹 / 一次好几个** →
  开「新建压缩文件」对话框并把它们填进输入列表。
- **置顶**（`视图 → 置顶`，4.5.0）：点一下把这扇窗口钉在所有窗口前面，再点一下放开，
  勾画在这一行左边，与「列设置」「工具栏」用的是同一枚勾。状态的唯一一份就是窗口自己那个
  `Topmost`——不另存布尔、**也不写进设置**：每次开机都有一扇挡在前面不是任何人想要的设置。
  钉住之后它自己弹出来的那些框（进度、确认、口令、设置）照常浮在上面，压不住；
  `Ctrl+Shift+N` 另起的那一扇是新窗口，从没钉开始。
- **图像预览**（`视图 → 图像预览`，4.6.0）：选中一张图，它就画在**左栏底下**那一格里（树在上、图在下），
  按原比例居中，不裁不拉扁，认 `.jpg .jpeg .png .gif .bmp .ico .webp .tif .tiff`。
  **只在真有一张图可看时占位置**：没选中、选中多个、选中的不是图，那一格整个收掉，不留一块空白；
  解不开时它留着并说一句为什么（太大 / 解码失败 / 读不到内容）——专门勾出来的东西空着却不说话，
  读起来就是"点了没反应"。这一行从 0.9.9 起一直灰着，现在它与工具栏那颗「查看」是同一个命令，
  首页上一起灰、开着包一起亮。口令包里的图预览不出来（回读内容那一路不带口令，缩略图同此）。
  4.6.3 修掉了"点它就崩"：根子在引擎门面的单条目读取上少加了一次引用，
  而那一路同时是缩略图、包内增删、修复搬成员、单文件取出、打开嵌套包共用的。
- **新建程序窗口**（`Ctrl+Shift+N`）与**管理员权限的那一扇**（`Ctrl+Alt+N`，4.0.0）：另起一个进程，
  当前开着包就把包一起带过去。命令行自己带上 `/task=open`——不带开关的那条是**双击**的语义。
  管理员那一条走系统标准的提权启动，**确认框由系统弹、由用户按**；按了取消就说"没起来"，
  不重试、也不悄悄退回不提权的那一条。

#### 解压与压缩

- **只有一个词：解压**（5.0.0）。「设置 → 解压 → 双击压缩包文件时」那一档、右键那一行、
  首页那颗、`Ctrl+E`，最后都汇成同一个任务：**读清单 → 按包里装着什么决定落点**。
  只有一个文件就直接解出来；所有内容都在同一个顶层文件夹里就把那个文件夹整个放出来
  （不再套一层同名文件夹）；零散一堆才收进与包同名的文件夹。界面上没有第二种"智能"解压。
  要自己挑地方的是**「文件 → 解压到…」**（`Ctrl+Shift+E`），那扇对话框里可以解压后删除源文件、
  记住设置，目录浏览用的是**系统**的选文件夹对话框（不自己画树，打开时停在当前目标路径；
  3.0.1 起删掉了「桌面 / 我的文档 / 我的图片 / 我的电脑」那一行快捷按钮——那一格本来就是可编辑下拉，
  上面两条路一步就到，留着一行只是让对话框高一截）。
- **撞名一次问清，不一个一个点**（5.2.0）：目标里已经存在的同名文件在开工之前先数一遍，
  有几个就在同一屏说完（名字列出前四个），三颗按钮是**全部重命名 / 全部覆盖 / 全部跳过**，
  按下去管的是这一次解压的**整批**撞名。以前是每个撞名文件弹一次 —— 四个文件撞名就要点四次，
  而那四次问的其实是同一个问题（"这一次撞名的怎么算"）。一个都没撞着就不弹，
  这一趟不该凭空多出一个框。目录不算撞名：解出一个目录到一个已有目录里是正常事。
- **两条都有的能力**：整包解压与逐条解压、百分比进度、可取消（**Esc 或右上角的叉号**，
  进度框上没有按钮）、**撞名一次问清**（全部重命名 / 全部覆盖 / 全部跳过，见下）、zip-slip 路径防护、
  非法字符清洗、ZIP 的 `.z01` 风格分卷拼接、口令保护包先问再解。**头加密的 7z**
  （`-mhe=on`，7-Zip 图形界面的默认）也算：打开时就先要口令。
- **撞上同名文件夹时建一个带序号的，不并进去**（4.8.0）：`报告` 被占用就依次叫 `报告1`、`报告2`，
  **占用算文件也算目录**。这一条不挑入口——首页那颗、「文件 → 解压到…」里那颗勾、
  那颗「新建文件夹」、双击那一档、右键那一条走的是同一份避让；「解压并删除」用同一套落点规则，
  成功后连分卷一起删。没跟着改的两处：压缩输出撞名还是 `报告 (2).zip`，
  解压时包内同名文件改名还是 `a (2).txt`——那两条撞的是**文件**，不是解压出来的文件夹。
- **解压跑完那一屏说「解压完成」**（4.8.1）：以前留着的那一屏永远写着「正在解压… 100%」，
  现在条子钉 100%、剩余时间与当前条目撤掉，跑完之后按叉或 Esc 只是关窗，不再假装取消了什么。
  「设置 → 解压 → 解压完成后不关闭进度窗口」这一档 4.9.0 按用户要求整个删了：窗口里那颗
  一律跑完即关，与右键、双击同一个结局。压缩那一档留着（那颗框留着的时候外面还压着
  「新建压缩文件」对话框，立刻关会让人以为没压成），它现在会说「压缩完成」。
- **不建主窗口的快路径**：双击那一档选了「解压」时的解压、右键压缩 / 解压 / 解压并删除——
  只有一根进度条（百分比 + 已处理体积 + 预估剩余时间），跑完自动消失。
- **压缩**：新建压缩文件对话框（格式、**5 档级别**、口令、分卷、排除 `Thumbs.db`、
  压缩后测试 / 删除源文件），ZIP 分卷由 Core 切块实现。级别是 `仅存储 / 极速 / 快速 / 标准 / 极限`，
  对应引擎 `-mx=` 的 0 / 1 / 3 / 5 / 9——前三档拼速度，标准档看平衡，极限档只管压得小；
  级别与方法无关，每个编码器自己把这个 0-9 翻译成自己的刻度。「文件名」默认跟着选中的东西走：
  压 `photo.jpg` 得到同目录的 `photo.zip`，一次压多个才叫「新建压缩」。
  格式下拉里只有引擎**真写得出来**的那 7 项（ZIP / TAR / TGZ / 7Z / GZ / BZ2 / XZ）；
  参考软件列出的 ZIPX / EXE / LZH / ISO / ZPAQ 是只读格式，摆在一个"一定要能做成"的列表里没有意义。
- **压缩方法**（2.2.0，高级设置面板）：这张表**按格式给**——ZIP 给
  `Deflate（默认）/ 仅存储 / BZip2 / LZMA / LZMA2 / Deflate64 / PPMd`，7Z 给
  `LZMA2（默认）/ LZMA / PPMd / BZip2 / Deflate / Zstandard / LZ4 / LZ5 / Lizard / Brotli / 仅存储`，
  TAR / GZ / BZ2 / XZ 这类单流或纯打包格式**没有方法可选**（下发 `-mm=` 会被引擎拒绝），
  所以界面上干脆不显示那个下拉，而不是显示一个假的选项。选中五种扩展方法之一时，
  下面多一行小字说明"这种包别的软件不一定打得开"。
- **压缩时预分配磁盘空间**（默认关）：开始写入前按未压缩总量占住簇——好处是一开始就知道这块盘放不下，
  而不是压到 90% 才失败；代价是这期间占的比最终包大很多。
- **压缩时不独占源文件**（默认关）：开着时压缩期间别的程序还能继续写/删这些源文件。
  它**不能**读取别的程序独占的文件——Windows 对谁都拒绝（备份语义也一样是共享冲突），
  这样的文件会被跳过，压缩结束时告诉你跳过了哪几个。

#### 包内编辑（3.4.0）

- **「编辑」那一排七项真的能用**：重命名（F2）、添加文件（Ins）、删除文件（Del）、
  压缩文件注释（Ctrl+Shift+M）、将文件复制到剪贴板（Ctrl+C）、从剪贴板粘贴文件（Ctrl+V）、
  复制文件完整路径。按当前开着什么包、选中了什么**逐项点亮或置灰**：改不动的格式
  （GZ / RAR / ISO…）只留复制类可用，目录只有改名那一项灰（改名要连底下每个成员的路径一起改）。
- 改写走的是引擎唯一的那个动作——"把要留的成员列出来"：删除是"不列出"，
  改名是"保留其余 + 按新名字加回这一个"。**同名的那几项要先问一句才覆盖**——
  "我粘个文件把包里原来的目录整个顶掉"不是用户能预料到的后果。
- **压缩文件注释只有 ZIP 有这一格**：7-Zip 的写入端属性表里根本没有归档注释项，
  所以这一格由我们自己改结束记录尾部那几个字节（不碰任何成员数据，也不重写整个包）。
- 剪贴板那两项把选中的东西解到 `%TEMP%\Andzip\Clipboard\` 再上剪贴板——
  放的是"我选的那几样"，粘出来包内结构还在。
- 「视图」里那三行从挂上来那天就没有命令的灰占位（**树形目录** F7、**压缩文件注释** F8、
  **视图样式**）4.7.0 连着背后那层一起删掉了；**树本身一行没动**，
  删的是"能不能把它藏起来"——它是目录导航与选中的引擎，也是图像预览那一格的宿主。
  4.3.0 还删过四条（启动画面、状态栏、置顶、颜色设置）与「帮助 → 转到用户论坛」，
  那五条里只有「启动画面」接过线，而它做的事「文件 → 关闭压缩文件」已经做过一遍
  （「置顶」4.5.0 又做了，这次是真的）。

#### 校验、测试与修复

- **算校验和**（`文件 → CRC` 那一排十一行，或工具栏那颗「CRC」，4.7.0）：CRC-32 / CRC-64 / XXH64 /
  MD5 / SHA-1 / SHA-256 / SHA-384 / SHA-512 / SHA3-256 / BLAKE2sp，最后一行 `*` 是"每一样都算"。
  名单与顺序照 7-Zip 的 CRC 子菜单，**算法名不翻译**；菜单那一层与工具栏那颗下拉从同一处构造。
  算哪几样跟着屏幕走：**开着包且有选中** → 那些成员**解压出来的字节**；**开着包没选中** →
  这个包文件本身；**首页** → 先挑文件（可多选）。第一种与列表里那一列 CRC 不是一回事：
  那一列抄的是包里记着的数，这一排是自己算一遍，两个数不一样就说明记录与数据不符。
  **不把它读进内存**：内核每解出 64 KiB 就喂一次摘要，所以 4 GB 的成员与 4 KB 的花一样的内存。
  进度走真字节数，取消落在项与项之间。读不到的那一项**照样列出来并写明为什么**，不从名单里消失。
  数字的印法照 7-Zip（4 与 8 字节的按小端整数印，更长的按字节串印），
  所以这里报的数与 `7z h -scrc…` 可以逐字对——这一条就是这么验过的。
  算法来自内核，其中 **SHA-384 与 BLAKE2sp 是内核门面自己补的**：上游一个把那行注册注释掉了、
  一个把实现藏在 RAR5 处理器里，两种都用已经 vendor 的那份 C 代码做出来了。
- **这一颗以前是「扫描」**（4.6.1 查清、4.7.0 换掉）：这台机器上 AMSI 一个提供程序都没注册，
  那颗按钮唯一能给的答案是"没人能答"，而**永远只能回答"问不到"的按钮比没有这颗按钮更糟**。
  AMSI 那一层整条删掉，从此不问任何人。
- **完整性检测**（工具栏「测试」/ `文件 → 测试压缩文件`，`Ctrl+T`）：整个包读一遍校验 CRC 但不落地，
  报百分比、已读体积与预估剩余时间；结果区分「数据坏了」与「根本没读成」（缺文件 / 口令错 /
  格式不支持），后者不会被写成"包坏了"。2.3.0 起坏掉的成员**一次全列出来**（引擎只报第一个，
  之后拿同一个句柄接着读剩下的），名单封顶 100 个，没查完的老实写成「另有 N 个成员没查完」；
  坏的是 ZIP 时结果框上直接给「尝试修复…」。
- **修复损坏的 ZIP**（`工具 → 修复压缩包`，或测试结果那一屏那颗）：**先量再问**——进度条里跑一遍
  结构扫描，骨架对得上就只说一句"没发现需要修复的结构问题"（并讲清这句只管结构、数据要靠「测试」），
  对不上才把三种模式摆出来，且把**扫到的问题**列在模式上方：**重建中心目录**（数据一个字节不改）、
  **续接分卷与被截断的包**（`.z01…` 拼成一条流，残缺的最后一个成员按实际剩下的写入）、
  **能修多少修多少**（逐成员真解压，解得出的重打包，解不出的列名）。
  **永远写副本，绝不动原包**；2.3.0 起修完**当场把新包读回来**，结果里那句
  「复查：N 个成员全部校验通过」是引擎读出来的，不是修复器自己的成绩单。
- **红线：不联网、不上传**。软件里**没有任何一条路径会把用户的内容发出去**。

#### 系统集成与设置

- **资源管理器右键一个压缩包**只有三项：**用 Andzip 打开**（在窗口里浏览内容，不会顺手解压）、
  **解压**、**解压并删除**。右键**其他文件或文件夹**只有两项：**压缩为 ZIP**（直接压）与
  **压缩到…**（打开「新建压缩文件」对话框，预填好输入与包名）——压缩包身上不出现这两项，
  把 zip 再压成 zip 不是谁想要的功能。双击那一条本来就是解压时，菜单里多出来的那行「解压」
  自己让位（让位的是多出来的那一条，不是双击那一条）；**两种设置下菜单里都只有一行「解压」**。
- **文件关联**：勾选即双击走我们，撤销时还原接管前的默认程序。默认程序可能被 Windows 挡住——
  `FileExts\<ext>\UserChoice` 优先级高于我们写的值，而那个哈希伪造不了（这本来就是防第三方抢默认用的）；
  这类扩展名会在设置里明确列出来，并给一个跳到系统设置的按钮。
- **设置窗口（F5）**：九个页面全部实装——常规、文件关联、上下文菜单、压缩、解压、查看、安全、
  高级、语言。每一页上的开关都真正接得上线；参考软件上有、这里做不到的项一律不摆，理由见下面的清单。
  **一个设置键只归一页管**（1.6.0 把「双击压缩包时…」从常规页搬到解压页就是这条规则的应用）。
  页面比对话框高，所以每一页的根节点是 `ScrollViewer`——这条是**真机截图**发现的：
  headless 断言"控件在不在"，看不出"看不看得见"。
- **「双击压缩包时」那一档的名字换过三次**：2.2.0 叫「智能解压」（那时它做的确实就是右键那件事），
  3.6.0 把**行为**换成就地铺开并改名「直接解压到当前文件夹」，3.9.0 按用户的话并回同一条任务，
  5.0.0 统一叫「解压」。界面上写的与代码里做的必须是同一件事（这条由断言钉住）。
  它**在 0.10.0-3.6.0 之间在真机上从来没生效过**：注册表里双击那条 `shell\open` 当年被加了
  `ProgrammaticAccessOnly`，而**被藏起来的动词当不了默认动词**——资源管理器往下找第一条看得见的，
  找到写死 `/task=open` 的那一条，于是双击永远开主窗口，设置怎么改都没用。3.7.0 改回来：
  `shell\open` 一律可见、命令行仍然不带开关，菜单上那一行的名字跟着设置换，重复的那一行由另一条
  自己让位。之前三次"修好了"都被同一件事骗过去：`Invoke-Item` 与 `Process.Start` 直接读默认值，
  不看动词可见性。
- **一台机器只留一份，注册表里也算**（3.2.0 立的是装的那一半，5.3.0 补的是 shell 那一半）：
  两棵 `Software\Classes`（`HKCU` 与 `HKLM`）在 shell 里是合并视图，**个人那一份压过机器的**。
  一个绿色版当年在 `HKCU` 里留下的动词会一直盖住装好的那一份 —— 实测过的现象是：装好的那份
  动词表已经是"只有一行解压"，右键菜单上却并排出现「智能解压」与「解压」，
  而双击跑的还是那个旧 exe（它的文件还在盘上，所以这不是死指针）。
  现在**机器级那一份启动时把两棵都校正**：只刷新那一棵里已经登记着的 `Andzip.*`，
  不创建新范围，不跨方向写（绿色版仍然只写 `HKCU`），值一样就不写、没写就不广播。
- **解压 / 压缩不再让桌面图标闪一下**（3.2.1）：每次通过关联启动都会"校正"一遍自己命名空间下的
  关联键，而它原先数的是"我重写了几个"而不是"有几个真的不一样"，于是每次都发一次全局
  `SHChangeNotify`，shell 丢掉关联与图标缓存重读，屏幕上所有图标整片闪一下。
  现在**值一样就不写、没写就不广播**。
- **口令只记在这次运行里**（4.3.0 起这是唯一的一层）：同一个包在这次运行中输过一遍就不再问，
  **退出程序就散了**——不写 `settings.ini`、不写注册表、不写日志。3.0.0 起下面还挂过第二层
  （跨重启，存在 Windows 凭据管理器里，配一扇只列"哪个包、什么时候存的"、永不显示口令本身的窗口），
  4.3.0 整层撤掉了：**它能做的只有"存着"与"删掉"，后果全归用户，而收益只是"少输一次"**。
  曾经开过那个开关的机器上，`Andzip/archive/…` 那些条目本程序不再读也不再管，
  要清得用系统的 `cmdkey /list` 与 `cmdkey /delete:`。
- **密码恢复**（`工具 → 密码恢复…`，2.9.0）：忘了自己设的口令时，把可能的口令**一个一个真读一遍**。
  两种选法——**穷举**（数字 / 小写 / 大写 / 字母+数字 / 自定义字符表，长度 1–12）与**字典**。
  四条不说假话的规矩：① **开工前先体检**，一个根本不是压缩包或压根没加密的文件会被当场拒绝并说明原因，
  而不是跑完一亿次之后报"这个范围里没有"；② **判对判错靠把那一格成员整段读完的 CRC**——
  7z 用错钥解出来是一段合法但错误的字节，只看"能不能打开"会大量误报；③ **速度在这台机器上现场标定**
  （ZIP 约 5000 个/秒、头加密的 7z 约 200 个/秒，差二十多倍），超过 30 分钟先问一句要不要跑，
  大到连总数都数不出来的那一种范围**直接不给开始**，「开始」灰掉的那一行同时写着为什么；
  ④ **找到、试完、被你停止是三句话**。恢复出的口令只显示在这一屏上供复制，**不落任何盘**；
  要不要顺手记进本次运行的口令表是单独的勾选，默认不勾。
- **帮助菜单**（2.8.0）：三条活的——**关于 Andzip（F1）**、**打开 Andzip 安装目录**、**转到官网**
  （地址在代码里只登记一处）。关于那一屏四行读数全是**现场取的**：版本取自程序集、
  压缩内核取自引擎自己的报告（所以内核没加载时它不会说好话）、许可证是这包里真的合并了 7-Zip
  与几个编码器的事实、"所在目录"指的是**这个正在运行的 exe 自己的目录**。
  **菜单里自称"已启用"的每一项都必须真的接到一条命令**，窗口构造时当场核对、对不上就抛——
  以前这句只写在注释里。「转到用户论坛」4.3.0 删了（那个地址永远不会有了），
  「转到帮助页面」2.8.0 删了（它和「转到官网」是同一个目标换两个名字）。
- **多语言**：中文 / 英文语言包，494 个键，键集与占位符逐一对齐，切档当场生效（见上面 5.1.0）。
- **工程化**：单文件裁剪打包、一次出两件产物、跨平台交叉编译、导出符号核对、CI 门禁、逐版本更新日志。

#### 安装与卸载

- **两条路**：`Andzip-Setup-*.exe` 双击出分页向导，或直接跑绿色版那个 exe（它什么都不写）。
  默认装 `%LOCALAPPDATA%\Programs\Andzip`（改位置时只有程序文件跟着走）；
  要勾才会动你的文件关联与右键菜单。「仅为我自己」这一条全程只写当前用户，不弹一次 UAC；
  选**「为所有用户」**（2.1.0）落到 `Program Files` + 公共开始菜单 + `HKLM`，
  需要管理员的只有两件事：往那一处装 / 卸，以及「只给自己装，但要先卸掉 `Program Files` 里那一份」（3.2.0）。
  **提权被拒就停在当前那一页说明白**，绝不悄悄降级成只给自己装；装与卸问的是同一句（2.4.0 补上卸那一半）。
- **一台机器只留一份**（3.2.0）：检测到另一作用域里已经装过的话，范围那一页会说清它是谁、在哪，
  并默认勾着"装之前先卸载那一份"——不勾就不给下一步。卸载该收哪一处，
  按"运行中的这一份 exe 在哪个位置"决定（`InstallLayout.ScopeFor`），
  所以同一台机器上"只给自己装"和"给所有人装"这两份历史都能被各自收干净。
- **卸载真的卸干净**（3.7.0 / 3.8.0）：以前卸完盘上"恰好"只剩一个 `Andzip.exe`
  （延迟删除只试一次，第一个撞的就是还锁着的 exe，失败被咽掉，`uninstall.bat` 反倒删掉了），
  而 ProgID 与扩展名默认值整片留在注册表里指着那个死路径。现在收尾重试到真的删掉为止、
  批处理先离开安装目录，并且**收不收那两处登记看的是"这条登记指着的是不是正在被卸掉的那一个 exe"**——
  用户后来自己在「设置」里勾上的关联也会跟着收回，别的软件与另一份 Andzip 一处都不碰。
  它还会顺手收回老版本欠下的那种"指着不存在的 ProgID"的扩展名默认值（3.8.0）。

### 未完成 / 已知限制

- **就地改写只到 ZIP / 7z / tar**：3.4.0 起能往已有包里添加、删除成员与改名（走引擎唯一那个
  "保留名单"动作），测试完还能一键进修复——但这三种以外的格式改不动：GZ / BZIP2 / XZ / ZSTD
  能创建却只有一条流，RAR / ISO / CAB 连创建都没有，那几种只能整包重压。
  「编辑」那一排在改不动的格式上就是灰的，拖进窗口的文件也不会"加进当前这个包"。
- **没有「生成 SFX」**（把解压程序与包拼成一个自解压 exe）。
- **密码恢复只会老实地试**：**单线程**，长度上限 12 位。没有掩码（"我确定前两位是 ab"）、
  没有口令变形（leet / 常见替换）、没有多线程分段并行。一个 8 位大小写加数字的口令在这台机器上要跑
  十几年——这一档不会假装更快，它只保证开跑之前把"要多久"说实话，
  并且跑不完的时候说的是"没试完"而不是"没有"。
- **深色模式只覆盖了我们的表面**：勾选框方框内部、滚动条槽仍由 SimpleTheme 画，在深色下偏浅
  （要清掉得给这几类控件各写一份 `ControlTheme`，清单在 `docs/界面设计规范.md` §10.4）。
  标题栏（1.7.0）、菜单弹出层与下拉列表、提示气泡（1.8.0 / 3.9.0）都已经归我们画了。
- **列表与树的行悬停没有那颗浮起药丸**：行是 `ListBoxItem` / `TreeViewItem` 模板画的，
  要浮起来得替它们重写 ControlTheme；行悬停仍是 SimpleTheme 的淡色底。
- **压缩包视图只到「浏览」**：列表右键菜单、双击预览、拖拽解压都没有
  （**图像预览面板 4.6.0 有了**）。拖过的**列宽**只在当前这一份视图里记住，
  关掉包再打开回到默认宽度；列的**显隐**跨重启。
- **条目「文件说明」（逐条目注释）不支持**，会回报警告而不是静默丢弃。
- **分卷只有 ZIP 真做**：7z / xz 的原生多卷输出未实现。
- **ZIP 的密码只支持 ASCII**（7-Zip 写入端自身的限制），用中文密码请改 7Z。
- **右键菜单是静态注册表动词**，不是 COM shell 扩展：Windows 11 上落在「显示更多选项」二级菜单里、
  一次只处理一个文件或一个文件夹、菜单标题渲染不出实际文件名。
- **默认程序可能被 Windows 挡住**（`UserChoice` 优先级更高，那个哈希伪造不了），
  设置里会把这类扩展名列出来并给一个跳到系统设置的按钮。
- **口令不跨重启**（4.3.0 起连这一层都不做了）：要"下次开机别再问"，请交给系统或浏览器自己的
  口令管理，别指望一个解压工具。
- **修复只支持 ZIP**：7z 的头是编码过的一整块，残缺后无法可靠重建，所以不碰——
  1.8.6 起这件事**在点菜单时就说明**，不再弹一个注定失败的模式对话框。
- **五种扩展压缩方法只对 7Z 开放**（Zstandard / LZ4 / LZ5 / Lizard / Brotli）。
  **ZIP 永远不给**——那些方法在 ZIP 里用的是非标准方法号，做出来的包 WinRAR、资源管理器、
  原版 7-Zip 都打不开，而用户会把这种包发给别人。这条与内核能力无关，是产品红线，
  两侧各有一条断言钉着。引擎也能写 `lz4` / `lz5` / `liz` / `br` 四种单流容器，
  界面上**没有**跟着放开：参考软件不列它们。
- **符号链接与 POSIX 权限**没接到界面上。
- **错误框里的异常文本仍是英文**（内核回传的消息直接显示）。
- 完整的逐条清单见 [`docs/开发记录.md` 第六节](docs/开发记录.md)。

## 四、架构一眼版

分层是**单向**的，界面永远看不到 native 的类型：

```
  Andzip.App          Avalonia 界面
        │             只调用 Core 的门面与选项记录
  Andzip.Core         深模块：小的接口 + 大量实现
        │             决定「事情怎么做」：命名、重名、路径安全、分卷、进度
  Andzip.Native       P/Invoke 外壳
        │             43 个 az_* 函数，UTF-8，__cdecl，不透明句柄
  andzip_core.dll     7-Zip 引擎
                      决定「字节怎么变」：识别格式、编解码、CRC、固实块、多卷拼接
```

两个值得单独说的判断：

- **接缝放在 Core 的四个静态门面上**（`ArchiveCreator` / `ArchiveExtractor` / `ArchiveReader` /
  `ArchiveTester`）。换引擎时界面一行都不用改——本项目实际上就这么做过一次。
- **错误模型是翻译而不是透传**。`NativeEngine.Translate` 把引擎错误码映射到 Core 原有的异常类型，
  P/Invoke 的错误码不会成为界面必须知道的契约。

完整推导（为什么接缝这么放、解压为什么有两条落地路径、`PROPVARIANT` 那个间歇性崩溃怎么定位的）
在 [`docs/开发记录.md`](docs/开发记录.md) 第三、七节。

## 五、怎么构建

### 前置

- **Visual Studio 2022/2026 的 C++ 工作负载**（引擎用）。CMake / Ninja 用 VS 自带的即可。
- **.NET 10 SDK**。
- 交叉编译 Linux 时需要 Zig（`native/scripts/provision-toolchain.ps1` 会下载便携版）。
- Windows 上建议用 PowerShell；下面命令在 Git Bash 里请写成 `powershell -ExecutionPolicy Bypass -File …`。

### 1. 先构建压缩内核

```powershell
pwsh native/scripts/build-windows.ps1 -RunTests
```

它会配置并编译 `andzip_core.dll`（约 284 个编译单元，需要几分钟）、跑 537 条原生断言、
核对导出符号恰好是头文件声明的 43 个 `az_*`，最后**把 DLL 暂存到
`src/Andzip.Native/runtimes/win-x64/native/`**。

最后一步是界面工程能找到引擎的前提。**跳过它的话 `dotnet build` 照样成功**，
只是程序一起来就显示「compression engine unavailable」。

### 2. 构建界面与业务层

```powershell
dotnet build Andzip.slnx -c Release
```

### 3. 跑测试

```powershell
dotnet test Andzip.slnx -c Release                      # xUnit：Core + 界面
dotnet run --project src/Andzip.Native.Tests -c Release # 控制台自检，必须单独跑
```

第二条不能省：`Andzip.Native.Tests` 是不带 xUnit 适配器的控制台程序，`dotnet test` 对它
只会还原、不会运行。

`Andzip.App.UI.Tests` 用 Avalonia 的 headless 平台装配**真实的窗口**去断言控件在不在、可不可用、
点下去设置有没有落盘，另外会把主窗口 / 设置页 / 修复对话框渲染成 PNG 供人眼核对。
一个必须知道的边界：**headless 平台不检查线程亲和性**，从工作线程改控件在这里不会抛——
所以进度上报这类跨线程的东西，界面测试要断言"回调落在哪个线程"，而不是"有没有炸"。

### 4. 运行

```powershell
pwsh run.ps1          # 构建 + 启动主程序
pwsh run.ps1 -Check   # 只构建 + 跑两套测试，不开窗口
```

等价裸命令是 `dotnet run --project src/Andzip.App`。在 Visual Studio 里双击 `Andzip.slnx`
之后直接 F5 也能起主程序。

标题栏应当显示 `Andzip (Professional) · 7-Zip 26.04 (x64) · Release · 60 formats / 7 writable`；
如果显示 `compression engine unavailable`，就是第 1 步没做或没暂存成功。

> 仓库里有好几个 exe，别搞混：**主程序**是 `dist/Andzip-v<版本>-win-x64.exe`（发布版）或
> `src/Andzip.App/bin/Release/net10.0/Andzip.exe`（开发版）。
> `build/native/bin/azgui.exe` 是内核自带的最小验证界面，`azcore.exe` 是命令行工具，
> `Andzip.Native.Tests.exe` 是自检——三个都不是主程序。

### 5. 打包（绿色版 + 安装器两件）

```powershell
pwsh build.ps1    # 版本 → 测试（不过就拒绝打包）→ 发布 → 内嵌核对 → 两件产物 → 对产物跑 /selftest
```

产物在 `dist/`：`Andzip-v<版本>-win-x64.exe`（单文件绿色版，下载即用）与
`Andzip-Setup-v<版本>-win-x64.exe`（「正常安装」：双击出安装向导）。

**安装器不是第二个程序，是同一个文件改了名**——它按自己的文件名判断身份
（`InstallLayout.IsInstallerFile`）。这样两件事同时成立：安装器与应用不可能版本不一致，
而装进电脑里的那份 exe 与绿色版是同一个字节流。安装只做五件事：复制自己到
`%LOCALAPPDATA%\Programs\Andzip`（向导里这一处可以改）、留一个 360 字节的 `uninstall.bat`、
建桌面与开始菜单的 `.lnk`（图标取 exe 内那张带透明的 ICO）、写卸载表、按勾选登记关联与右键菜单。

**卸载没有单独的 `uninstall.exe`，但有能双击的 `uninstall.bat`**：真卸逻辑在
`Andzip.exe /uninstall` 里（它知道两种作用域、快捷方式、注册表，以及"删掉正在运行的自己"那件事），
一个独立的 exe 要么是那 20 MB 的第二份拷贝、要么也只是启动上面那一条的壳——
壳用 90 字节的批处理就是同一个东西，还不需要目标机器上有编译器。
它跟着安装目录一起收回；开始菜单里那一项「卸载 Andzip」与控制面板那条 `UninstallString`
走的也是同一条路。卸自己正在跑的那个 exe 时，Windows 报的是"拒绝访问"而不是"正在使用"，
而"退出之后再删"要等的是**进程真的退出**、不是睡两秒——这两处（2.0.0）都改成按
`Wait-Process -Id <自己>` 等。

**打包会扫描产物字节**确认 `andzip_core.dll` 真的在里面——这个失败原本只在运行时才暴露。
单元测试跑的是**未裁剪的 `Andzip.dll`**，发出去的却是单文件 + 裁剪 + 压缩过的 `Andzip.exe`，
而有些故障只活在这条差别里（1.8.3 那次安装器建不出快捷方式：1101 条断言全绿，产物是坏的）。
所以 `build.ps1` 最后一步**直接执行产物**：`Andzip.exe /selftest` 在临时目录 + 探针注册表键里
真装一次、真卸一次，25 项逐条打 `ok` / `FAIL`，非零退出就拒绝出包。
出包之后还有一步真屏幕核对，脚本是 `tests/gui-probe.ps1`——它真的启动
`dist/Andzip-Setup-*.exe`、真的把鼠标点到屏幕坐标上、真的截那块像素
（`PrintWindow` 在 Avalonia 的 GPU 表面上只会是一片黑，所以走 `CopyFromScreen`）。
这两步从 1.8.4 起是固定动作，不再靠"想起来才做一次"。

体积的实测结论（哪些开关有效、为什么不是"换掉链接库形式"能解决的）记在
[`docs/开发记录.md` 第四节第 5 条](docs/开发记录.md)。

### 6. 一次性跑完所有平台（可选）

```powershell
pwsh native/scripts/verify-all-targets.ps1   # Windows 动态 + Windows 静态 + Linux 三个目标
pwsh ci.ps1 -Static                          # 本地等价于 CI 的 Windows 作业
```

## 七、许可证与出处

`native/` 合并了多个上游，机器可读的来源记录在 `native/third_party/MANIFEST.json`。

| 组件 | 许可证 |
|---|---|
| 7-Zip 引擎（`C/`、`CPP/`，原样 vendor，未修改一行） | LGPL-2.1-or-later **附 unRAR 限制** |
| zstd / lz4 / brotli / lizard 等 | BSD-3-Clause / MIT / BSD-2-Clause 等 |
| 上述组件的 7-Zip 封装 | MIT |
| Zig（仅用于交叉编译，不进产物） | MIT |
| SharpZipLib（**只有测试工程引用**，生产代码不依赖） | MIT |

`src/`、`tests/` 以及 `native/src`、`native/include`、`native/tools`、`native/tests`
是本项目的原创工作，沿用 Andzip 自身的许可证。

发布前必须复核两件事：

1. **unRAR 限制**：可以解码 RAR，但不得据此支持 RAR 创建。要宣传 RAR 能力先对照条款。
2. **LGPL 路线**：`andzip_core` 以 DLL 形式动态链接。若改成静态链接发布，需要按 LGPL 提供相应便利。

> 界面与产品设计参考 Bandizip。上游原始压缩包（`cankao/`）与逆向参考语料（`Bandizip-RE/`）
> 都**不在本目录内**：日常构建不需要它们，只有重新 vendor 内核时才需要 `cankao/`。
