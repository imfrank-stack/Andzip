# Andzip 界面设计规范

> 版本 1.0（随 1.4.0 引入）· 适用对象：`src/Andzip.App` 里全部用 C# 代码构建的 Avalonia 控件
> 约束的边界：**这份文档里的每个数值都必须能在代码里找到对应令牌**；做不到、或引擎/主题做不到的，
> 一律写在第七节「不做的事」里，而不是留一句"应当更现代"。

---

## 一、设计语言与四条原则

选 **Fluent 2 为骨架**，因为 Andzip 是一个 Windows 桌面工具：窗口、菜单、对话框、状态栏这些
形状本身就是 Windows 的母语，硬套 Web 那套（大留白 + 卡片瀑布）会既不像系统、也不像参考软件。
但 Fluent 的"材质"那一半（Acrylic 模糊、Mica）**不用** —— SimpleTheme 没有背景模糊能力，
写进规范就是空头支票（见第七节）。

四条原则，冲突时按顺序让步：

1. **可辨识优先于好看。** 工具栏、菜单、列表是用户干活时盯的东西，配色不能抢内容。
   蓝色带只出现在工具栏，内容区一律白/极浅灰。
2. **每个可点的元素都要有反馈。** 悬停、按下、焦点三种状态至少能看到一种变化，
   禁用态必须明显"按不动"。没有反馈的可点物比灰掉更糟 —— 用户会反复点。
3. **圆角与间距成体系，不许逐处调。** 只有第四节的 5 档圆角和 7 档间距可以用；
   看到 `new Thickness(7, 3, 11, 5)` 这种数字就是违规，无论它"看起来"多合适。
4. **平滑不等于动效。** 颜色/透明度过渡可以要，布局位移不要 ——
   一个压缩工具会在进度里跳动，位移会让人觉得卡。

## 二、落地前提（实测，不是假设）

规范能写这么细，是因为这三件事在 headless 里量过像素确认过
（`tests/Andzip.App.UI.Tests/ChromeCapabilityTests.cs`）：

| 事实 | 结论 | 对设计的影响 |
|---|---|---|
| SimpleTheme 的 `Button` / `TextBox` / `ComboBox` 模板**真的吃** `CornerRadius` | 设 8 之后四角回到页面底色；不设四角仍是填充色 | 圆角可以当主手段用，不是装饰性愿望 |
| 应用层 `Style(x => x.OfType<Button>().Class(":pointerover"))` **压不过**主题内部 `ControlTheme` | 注入悬停底色后中心像素不变；而 `:pressed` 由主题自己变灰 | 悬停态一律走 `Chrome` 助手（代码里接 `PointerEntered/Exited`），不写伪类样式 |
| headless 的 `MouseMove` 会真的触发 `PointerEntered/Exited` | 各 1 次 | 交互态可以被测试钉住，不用只靠人眼 |
| **`Border.BoxShadow` 真的画得出来**（1.7.0 补测，`ShadowCapabilityTests`） | 卡片右缘外 4px 的像素比画布暗 | 阴影可用 —— 但**只在自绘的 `Border` 上**：`BoxShadow` 是 Border 的属性，Button/TextBox 这些模板控件没有这个属性，导航药丸那一类仍然只能靠底色差（规范 5.8） |
| **无边框 + 透明窗口在这台 Windows 10 19045 上成立**（1.7.0 实测，截图见开发记录第七节第 31 条） | 圆角外那圈透明边距能透出后面的窗口，阴影也画得出来 | 主框体自己就是那张圆角阴影面板，不需要系统标题栏 —— 顺带把 1.5.0 那条"深色标题栏翻不深"变成不存在（标题栏是我们画的） |
| `ToggleButton` 的模板对 `:checked` 有它**自己的**底色 setter（1.7.0 补测） | 把轨道色设成控件自己的 `Background` 会被盖成模板灰，"开着"和"关着"只差滑块位置 | 开关的视觉全部画在 Content 里那颗自绘 Border 上，控件本体只负责行为（键盘、焦点、`IsChecked`） |
| **菜单弹窗的根就是一枚 `Border`**（1.8.0 实测，`HoverAndPopupTests`） | 子菜单 / 右键菜单 / 下拉列表挂在**本窗口**的 `OverlayLayer` 上（`OverlayPopupHost`），`Popup.Child` 是枚直角、白底、1px 灰边的 `Border` | 弹出框的圆角与阴影直接改那枚 Border，不必替 `MenuFlyoutPresenter` 重写 ControlTheme |
| **弹窗宿主 `ClipToBounds=true`，影子画不出宿主矩形**（1.8.0 实测：把裁剪关掉也没用，宿主自己的矩形就是裁剪框） | 给那枚 Border 设 `BoxShadow` 后，外沿 4px 一个像素都不变 | 要影子就必须让**宿主变大**：给 Border 加 `Margin`。**只能加右下、不能碰 `Popup` 的偏移** —— Avalonia 按含 margin 的外框定位弹窗，四周都留再收回偏移会把面板推到锚点身上，盖住打开它的那一项（1.8.3，规范 5.10） |
| **`ToolTip` 的模板里只有一枚 `ContentPresenter`，没有 Border**（1.8.0 实测） | 设 `CornerRadius` 没有任何效果 —— 没有东西可以圆 | 气泡只能换模板（`Chrome.InstallBubbles` 用一条应用层 `Style` 设 `Template`）。**这条实测有效**：说明"应用层样式压不过 ControlTheme"那句只适用于伪类 setter，不适用于模板 |
| **`MenuItem` 的高亮画在模板里的 `Border#root` 上**，值由 ControlTheme 的伪类 setter 给（20% 品牌蓝） | 应用层样式改不动它；但**实例上的本地值压得过 setter** | 菜单栏悬停要"轻微置灰"就在 `PointerEntered` 时给那枚 Border 写本地值、`PointerExited` 时 `ClearValue` 交还给模板（展开态的高亮仍归 SimpleTheme 管） |
| **图标可以带真透明**：`assets/andzip.png` 是 512×512 RGBA、四角 alpha=0，`make_icon.py` 按 alpha 外接框裁出七档 | 16/24/32 那三档 DIB 的四角 alpha 实测为 0（`AssetIconTests` 逐档读字节） | 桌面 / 开始菜单 / 任务栏的图标是圆角带透明的，不会带一圈白底 |
| **`TreeView` 的模板自带一圈 `#888888` 描边**（1.8.5 实测，`TreePaneLineTests`；真机截图里 1 DIP 在 150% 下就是 2 设备像素的实线） | 只设 `Background = Transparent` 关掉底，那一圈框照旧在 —— 用户为"左边的线"报了三次，1.8.0 改的是分栏线，动的从来不是它 | **模板控件的底与框是两个属性**：`_tree.BorderThickness = 0` 要显式写。少了它，"整窗一张面板 + 两栏之间一根发丝线"（5.1）在屏幕上直接不成立 |
| **`Button` 模板在 `:pressed` 上自己涂 `#686868`，应用层给 `Background` 写的局部值压不过它**（1.8.7 实测，`SettingsNavTests`；用户截图量的） | 设置页导航按下去整块发黑、文字几乎读不出；悬停我们能接管（`PointerEntered` 写局部值），按下不能 | **要精确控制状态的控件，视觉画在 Content 里那颗自绘 `Border` 上**（开关轨道、导航药丸同一套路），按下那一档归 `Surface.Pressed` |
| **但给那枚模板子元素自己写局部值就压得过**（1.8.8 实测，`ChromeCapabilityTests`：同一套合成输入下，裸按钮按住是 `#686868`，接过的按钮按住是 `#E9EDF1`） | 本地值的优先级在样式之上，主题的伪类 setter 从此写不进那枚 `PART_ContentPresenter` | **`Chrome.PinFace`**：把控件自己的底色/描边/圆角抄到面皮上，之后每一次换档都重抄一遍。`Lift`/`Ghost`/`Accent`/`Danger`/`ToggleSwitch` 内部已经接了；**直接 `new Button` 而不走这几个方法的，一律漏接** —— 1.8.8 扫出 20 处，用户那句"好多地方点击瞬间会变黑"就是这 20 处 |
| **指针事件跑在状态置位之前**（1.8.8 两次于真机量到：按住那一刻是 `#FFFFFF`，改成读属性之后又错一次是 `#F6F8FA`，都不是按下那一档） | `Button.OnPointerPressed` 里先发 `PointerPressed` 再 `IsPressed = true`；而且一按下去指针就被捕获，紧接着还会补一次 `PointerExited` —— 按"哪个事件最后到"决定，按住那一刻会退回悬停档甚至清成透明 | 状态的**触发与读取都只认属性**：`PropertyChanged` 里认 `IsPointerOver` 与 `IsPressed`，在回调里现读现画。指针事件不参与决定 |
| **`ComboBox` 按住时那块灰不来自它自己的面皮，而来自模板里内嵌的 `ToggleButton#toggle`（那 16px 宽的箭头）—— 它有自己的面皮**（1.8.8 实测：外层 `PART_ContentPresenter` 仍是 `null`，箭头那枚却是 `#686868`；1.9.0 复测：只钉外层时那一格里 445 个 `#686868`） | 点开下拉的那一下，字段是白的、右边一小格是黑的 | `Chrome.PinFace` 除了抄自己那枚，还往子树里找内嵌的 `ToggleButton` 一起抄（1.9.0）。**只认 `ToggleButton` 这一种**：模板里还会冒出 `TextBox` 与 `Popup`，把它们一起钉住会连下拉列表里那些行的主题态一并钉死，代价比这一格大 |
| **`ComboBox` 自带一圈 `#888888` 描边**（1.9.0 真机量到：字段下边缘 243 个 `#888888` 像素，1 DIP 实线） | 与 1.8.5 那圈树描边同一族 —— 同一张表单里输入框是 `Border.Strong`，下拉框重两级，读起来像"这个框被加重了" | `Chrome.Picker` 显式写 `BorderBrush = Line.Strong` + `BorderThickness = 1`；换档时描边不动（`TrackStates` 那两档传同一枚），只有底色换 |
| **headless 的合成按住真的会触发主题的伪类**（1.8.8 实测；1.8.7 那条"headless 复现不了这块灰"是错的，错在拿一颗已经接过 `Chrome` 的按钮去试） | 同一套 `MouseMove` + `MouseDown`：裸按钮 `#686868`，接过的 `#E9EDF1` | "按下这一刻"可以进回归用例，不必全留给真机。真机仍然要跑（合成输入不复现影子与 DPI 取整），但它不再是这类问题唯一的证据 |
| **`GridSplitter` 只改它「直接父级」那枚 Grid 的列**（1.8.9 实测，`SeamDragTests`：套一层宿主 Grid 之后，在那条线上按住拖 120，左栏 292 → 292，一动不动） | 光标对、按得住、拖起来很顺 —— 只有布局不变。用户的话是"这条线应该是可以拖的，现在无法调整" | 分栏控件必须**直接**是那个多列 Grid 的孩子。要"线 1px、命中 8px"两层，就把线做进 `GridSplitter` 自己的 `Template`（实例级模板压得过 ControlTheme，与提示气泡同一招），**不要再套一层宿主** |
| **模板根留 null 底色，整条 8px 带子只有那 1px 点得着**（1.8.9 实测：把模板根的 `Background = Transparent` 删掉，在带的边上（离线 6px）按下拖动 → 左栏仍是一动不动） | "命中区 8px"这件事在视觉上完全成立、在命中上完全不成立，而差的那 6px 正是用户瞄不准的时候 | 命中层要有一层**可命中的填充**（`Transparent` 算填充，null 不算）。用例故意**不瞄在线上**，量的才是那 8px |
| **控件"刚挂上树"那一帧可能还没应用模板**（1.9.1：`Chrome.PinFace` 在 `AttachedToVisualTree` 后排的 `Render` 优先级那一发，理论上会抄到 null 面皮 = 抄了等于没抄，而 **headless 里永远测不到** —— 它同步就把模板建好了） | 表现是"我这台好、你那台漏黑"，量不到、复现不了、也没法用一条用例证明修好了 | 兜底一发排在**首次量到尺寸**之后（`Bounds` 非零 ⇒ 布局跑过 ⇒ `OnApplyTemplate` 一定跑过），只补一发。这类"时机在真机上才成立"的前提，写进注释比写进用例便宜，但必须写 |
| **headless 的命中测试要先有一帧渲染过**（1.8.7 实测） | 没量过像素就直接 `GetVisualsAt`，连行中心都返回空表 —— 看起来像"整棵树都点不到" | 命中类断言之前先 `Pixels.At(window, 同一个点)` 一下；否则会把**环境的假象**当成产品缺陷去修 | | 没量过像素就直接 `GetVisualsAt`，连行中心都返回空表 —— 看起来像"整棵树点不到" | 命中类断言之前先 `Pixels.At(window, 同一个点)` 一下；否则会把**环境的假象**当成产品缺陷去修 |
| **换页时把同一个控件从旧父节点摘下来"立刻"挂到新的，做不到**（2.0.0 实测：向导走到位置页、上一步、再下一步，抛 `The control TextBox already has a visual parent Grid`） | `ContentControl` 换 `Content` 之后，旧子树还要等一次布局才放开视觉父节点，而插入的校验是**当场**问的 | **向导的页面只建一次，翻页只改 `IsVisible`**（`InstallerWindow.GoTo`）。要"每次重建"就得连用户填的框、他刚拨过的开关一起重建，那既是状态丢失也是这一炸 |
| **`IsVisible` 不继承**：父节点藏着时子节点的 `IsVisible` 仍然是 `true`（2.0.0 实测，`VisualQuery.VisibleTexts` 改之前） | 按逻辑树读"屏幕上看得见哪些字"会把不在当前这一页上的文案也算进去 —— 于是"卸载完成页上没有那颗按不动的勾选框"这类断言会**假绿** | 测试里问"用户看得见什么"必须自己把可见性一路带下树（`ShownDescendants`）。这条改动让 131 条界面用例全部重跑一遍才敢信 |
| **`RadioButton` 在 Avalonia 里按"同一个父面板"自动成组**（2.1.0 实测：两枚都塞进同一颗 `StackPanel` 时选第二个会弹开第一个 —— headless 一条 + 真机截图各看过一次，不写 `GroupName`） | 「为哪位用户安装」那一页的互斥不用任何额外代码 | 成组的单选钮**必须**放同一个父容器；中间隔一层面板就变成两组各选各的 |
| **`Process.Start` 配 `Verb = "runas"` 必须 `UseShellExecute = true`，而且调用会阻塞到用户在系统确认框上做完决定；被拒时抛异常（错误码 1223），不是返回 null**（ShellExecute 的行为，**这条本机没实测**：这台机器的账户不是管理员，弹的会是别人口令的框，不该由自动化去按） | 拒绝时抛异常（错误码 1223），不是返回 null —— 所以"提权没成"只能靠接住异常来判断 | 提权这件事不能放在进度条后面做：要么在翻页之前就问清楚，要么就别问（5.11）。也不许在没被同意时悄悄换成"只给自己装" |
| **`ToggleButton.IsChecked` 的初值是 `false`，不是 `null`**（2.0.0 实测：安装向导位置页上两个附加任务开关灰着，而上一页明明写着"还没有安装"） | "这个开关我还没设过初值"这件事不能用 `IsChecked is null` 问，那个判断永远不成立 | 初值自己记一次标志位（或直接在建控件时设），别问控件 |

还有一条约束：本项目**没有 XAML**，控件全在 C# 里 new。所以令牌必须是 C# 常量
（`Design.cs`），而不是资源字典 —— 后者在这套代码结构里只会变成第二套没人同步的真相。

## 三、色板

> 本节按 Fluent 的习惯写令牌名（`Border.Subtle`、`Danger.600`），代码里的实际标识符略有出入
> （`Design.Line.Subtle`、`Design.Semantic.Danger`）—— 对应关系全在第九节的映射表里，
> 那张表才是查代码的入口。

### 3.1 品牌蓝（主按钮、选中态、链接、工具栏图标）

对比度都是按 WCAG 2.1 公式实算的（`PaletteContrastTests` 逐对断言），
"浅色 / 深色"两列分别是两套调色板下的同一个配对。

| 令牌 | 浅色 HEX | 深色 HEX | 用在哪 | 对白/对底文字对比（浅 / 深） |
|---|---|---|---|---|
| `Brand.600` | `#0F6CBD` | `#1B5E9E` | 主按钮底色、开关的开启轨道、工具栏图标描边 | **5.38 / 6.68 ✅ AA** |
| `Brand.700` | `#0C5AA0` | `#144A80` | 主按钮按下 | 6.9 / 8.2 ✅ |
| `Brand.500` | `#2E86D6` | `#5CA8E8` | 主按钮悬停（比默认更亮，读作"浮起"） | 3.5 / 2.9 ⚠️ 只用于**大字/图标**，不用于 12-14px 正文 |
| `Brand.100` | `#E1EEFB` | `#1E3A52` | 列表选中行底色、视图栏当前项 | 正文压在上面 13.4 / 9.8 ✅ |
| `Brand.50` | `#F2F7FD` | `#17293B` | 信息条底色、悬停行 | 正文压在上面 16.6 / 12.4 ✅ |

> 深色那一列有个反直觉的决定：**主按钮的蓝要更"深"而不是更"亮"**。
> 常见做法是把强调色提亮以求"在暗处也显眼"，但它是白字的底 —— 提亮会把对比度打到 AA 以下；
> 而选中行、信息条这类"底"在深色下要反过来压成深蓝（`#1E3A52`），因为它们是**浅字的底**。
> 同一个"品牌蓝"在两套调色板里承担的角色不同，所以不是同一个亮度。

**1.7.0 起品牌蓝不再铺成一条工具栏带**。以前那条实心蓝是"没有阴影可用"时的产物：
要把顶部与内容分开，只剩"换一块重颜色"这一招。现在顶部是一张白色卡片（规范 5.1），
蓝退到**图标描边**上 —— 同样的辨识度，少一大块饱和色。

工具栏按钮的三态因此换了方向：卡片是白的，悬停只能**往下压一档**，
叠半透明白等于没有反馈。

1.8.0 起这颗药丸**还带一层外阴影**（`Shadow.Lift`）—— 用户给的原话是
"鼠标扫过就出现带阴影的圆角框"。阴影画不出来不是设计问题而是实现问题：
`BoxShadow` 只存在于自绘的 `Border` 上，所以 `Chrome.Lift()` 在控件**底下垫一枚 Border**，
控件自己的底色留透明。看见的灰与影都来自那枚药丸。

| 状态 | 浅色底 | 深色底 | 视觉 |
|---|---|---|---|
| 静止 | 透明（=卡片白） | 透明（=卡片深灰） | 与卡片同色 |
| 悬停 | `Surface.Muted` 药丸 + `Shadow.Lift` | 同 | 压深一档的**圆角 + 浮起** |
| 按下 | `Surface.Pressed` 药丸 + `Shadow.Pill` | 同 | 再深一点、收回去一点（1.8.8：原来写的是 `Border.Subtle`，与悬停只差 3/255，屏幕上读不出"按住了"） |
| 禁用 | 图标与文字 `Ink.400` | 同 | 明显按不动（收不到指针事件，药丸永远不出现） |

**按下这一档必须由我们把面皮钉住才看得见**（1.8.8）：药丸垫在控件底下，控件自己留透明，
而 SimpleTheme 的 `:pressed` 会绕过这句话，直接往模板里那枚 `PART_ContentPresenter` 涂一整块
`#686868` —— 于是"再深一点"变成"整块发黑"。解法只有 `Chrome.PinFace`（把控件自己的底色抄到那枚
子元素上，本地值压得过伪类），`Lift` / `Ghost` / `Accent` / `Danger` / `ToggleSwitch` 内部都已接。
**新建按钮必须走这几个方法之一**，直接 `new Button { … }` 就是漏接；这一条由
`DesignTokenTests.EveryButtonPinsItsTemplateFace` 扫源码把关（1.8.8 一次性扫出 20 处漏接）。
另一条同一来源的规矩：**换档只由 `IsPointerOver` / `IsPressed` 这两个属性触发**，
不由指针事件触发 —— 事件跑在置位之前，当场读到的是旧状态（规范 §二那条实测）。

**菜单栏（文件 / 编辑 / …）是唯一的例外**：它悬停时**只轻微置灰，不带阴影**（`Chrome.MenuGrayHover`）。
那排字是导航不是动作，浮起来会让一屏顶部不停跳动；SimpleTheme 自己给的是 20% 品牌蓝，
读起来像"这一项被选中了"，所以一并换掉。

### 3.2 中性色（一张表面 + 发丝边）

1.7.0 起**整块窗口就是一张表面**：标题栏、菜单、工具栏、树、列表、状态栏全在同一块上面，
中间只有一根根 1px 的线。上一版那种"灰画布 + 四张白卡片"被否掉了 ——
一屏四块各自发光的白板，用户的评价是**割裂**。

## 四、圆角、间距、字号

### 4.1 圆角（只有这 6 档）

| 令牌 | 值 | 用在哪 |
|---|---|---|
| `Radius.Xs` | 3 | 勾选框、小徽标、进度条内衬 |
| `Radius.Sm` | 6 | **默认**：按钮、输入框、下拉、菜单项、列表行内元素 |
| `Radius.Md` | 8 | 工具栏大按钮、卡片、对话框内的分组底、缩略图、弹出框 |
| `Radius.Lg` | 12 | 浮层、进度窗口里的信息卡 |
| `Radius.Panel` | 22 | **整块窗口那张面板**（主窗口、九个对话框、设置窗口） |
| `Radius.Pill` | 999 | 状态胶囊（如"本次运行已记住 N 个包的口令"） |

两条硬规则：
- **嵌套圆角要减去内边距。** 外 8 / 内距 4 → 内层用 4，不能内外都是 8，那会看出"双层边"。
- 全窗口 0 圆角的地方只剩两处：列分隔条、树/列表的选中行高亮条（它们贴边，圆了会露缝）。

`Panel` 为什么单独一档：它是全屏最大的一块，**同一个半径在不同尺寸的块上读起来不一样** ——
16px 用在一颗 40px 的按钮上是"圆角"，用在一块 1040px 的面板上就是"没裁干净的矩形"。
1.8.0 之前面板复用 16，用户的评价是角落"不自然"；参考图量出来约 22。

### 4.2 间距（4px 栅格，只有这 7 档）

`Space.1=4 · 2=8 · 3=12 · 4=16 · 5=20 · 6=24 · 8=32`

| 场景 | 值 |
|---|---|
| 图标与文字之间 | 8 |
| 按钮内左右内距 | 12（工具栏大按钮 14） |
| 表单行距 | 10 → 归到 **12** |
| 分组与小标题之间 | 20 |
| 窗口内容区内边距 | 20 → 归到 **24** |
| 对话框按钮与正文之间 | 24 |
| 状态栏左右内距 | 10 → 归到 **12** |

出现"归到"就说明旧代码里的值不在栅格上 —— 这次改版把它们抬到栅格上，之后新增控件只能从表里取。

### 4.3 字体与字号

```
FontFamily: "Segoe UI Variable Text", "Segoe UI", "Microsoft YaHei UI", sans-serif
```
（Windows 11 用 Variable，Win10 自动回退到 Segoe UI；中文回退到雅黑 UI，避免宋体在 12px 下糊。）

| 令牌 | 字号/字重 | 用途 |
|---|---|---|
| `Type.Caption` | 12 / 400 | 状态栏、列说明、hint 文字 |
| `Type.Body` | 14 / 400 | **默认**：菜单、列表、表单、按钮 |
| `Type.BodyStrong` | 14 / 600 | 表头、对话框标题行 |
| `Type.Subtitle` | 16 / 600 | 设置页分组标题 |

行高：正文 1.4，标题 1.25（Avalonia 用 `LineHeight`，14px 正文取 20）。

### 4.4 阴影（只有这 3 档）

每一档都是**贴地的接触影 + 弥散的环境影**，其中接触影那一层**不偏移、带扩散**（四周都要有，见第 5 条）。
单层大模糊会糊成一片灰雾，看着脏；分层才有"浮起来"而不是"变暗了"的感觉。

| 令牌 | 浅色的几层 | 深色 | 用在哪 |
|---|---|---|---|
| `Shadow.Floating` | `0 1 3 / #120B1E33` + `0 0 6 1 / #1F0B1E33` + `0 6 14 / #1F0B1E33` | `#33` + `#59` + `#59` | 整块窗口面板浮在桌面上：主窗口、设置窗口、每个对话框 |
| `Shadow.Lift` | `0 2 10 / #240B1E33` + `0 0 3 1 / #1F0B1E33` | `#73` + `#59` | 一块"能被指到"的小面：悬停药丸、弹出的菜单与下拉列表、提示气泡 |
| `Shadow.Pill` | `0 1 2 / #1A0B1E33` | `#66` | 小件：开关的滑块 |

七条规矩：

1. **影子的颜色不是黑的**，是品牌深墨蓝（`#0B1E33`）。灰黑影子在白底上发脏，带一点冷的墨色才干净。
2. **阴影只放在自绘的 `Border` 上**。`BoxShadow` 是 `Border` 的属性，模板控件（Button/TextBox/CheckBox）
   根本没有这个属性 —— 所以要么像 `Chrome.Lift()` 那样在控件底下垫一枚 Border（首页控件、标题栏按钮），
   要么就像设置页导航药丸那样退回到"底色差 + 描边"（规范 5.8）。
3. **面板不描边**（1.8.1）。参考图里那张卡片没有任何描边：边界是"卡片比背景暗/亮一档 + 一层软影"
   读出来的。一圈均匀的灰线，任何方向的光都投不出来，它只会读成"贴上去的"。
   主窗口与九个对话框原来都有 1px `Line.Subtle` 的边，去掉之后角落才自然。
4. **阴影必须整个装进透明边距以内**（`Design.Float.Margin` = 20 DIP）。窗口客户区就是渲染边界，
   影子伸出去会被**齐刷刷切一刀**，四个角最明显 —— 这是 1.8.0 那版"不自然"的第二条原因
   （当时弥散层能伸到 13 DIP 外，边距只有 12）。这条由 alpha 通道把关：
   窗口最外一圈六个点（四条边 + 两个下角）必须 `alpha == 0`，而贴面板外沿 2px 必须不透明。
5. **每一档都得四周有东西，不许只往下偏。** 同一块影子在不同尺度上读法不同，但"只往下偏移"
   在两种尺度上是同一个错：药丸只有几十像素高，只往下偏的话**上方读不出任何东西**（1.8.0 实测差 1/255）；
   整块面板比药丸大得多，只往下偏的话顶边只剩 2px 模糊的余量，压在浅色桌面上就是
   "窗沿和背景连成一片"（2.4.0 用户原话：「顶部也要有阴影，否则会和背景分不清」）。
   两次的解法是同一个：**加一层不偏移、带扩散的接触影**（`Lift` 的 `0 0 3 1`、`Floating` 的 `0 0 6 1`）。
   判据是"边外那几像素比远处暗多少"，不是"有没有设 `BoxShadow`" —— 后者属性读回来永远是对的。
   真机量的（白桌面，面板上沿之外）：`#FFFFFF → … → #E3E6E9`，越靠边越暗。
   反过来，**给面板一圈均匀的接触影不等于给它描边**（见第 3 条）：那一层是虚的、往外衰减的。
6. **窗口内部不再有阴影**。浮起的只有"整块面板"这一层；内部再放带影子的卡片，
   就是 1.7.0 被否掉的那版"一屏四块白板"。**悬停的那颗药丸是这一条的例外**：
   它表达的是"指针在这里"这个瞬时状态，不是一层永久结构。
7. **最大化时圆角与透明边距要收掉**（`MainWindow.FitSurfaceToState`）：留着一圈，
   最大化后四周会露出桌面、窗口还比工作区小一圈 —— 那是"没铺满"，不是圆角好看。

`Shadow.Lift` 的第二层**不偏移、带 1px 扩散**，这是有原因的：只往下方偏移的影子，
在药丸**上方**读不出任何东西（实测差值 1/255），而用户要的"带阴影的圆角框"必须一眼看得见。

## 五、组件规范

### 5.1 主窗口骨架（整窗一张面板）

```
透明边距（20px，画圆角与阴影用 —— 影子伸不出去就会被窗口切一刀）
└ 面板 Border：Radius.Panel 22 + Shadow.Floating + Surface（**不描边**，规范 4.4 第 3 条）
  ├ 自绘标题栏（40）：应用标记 + 菜单栏 ……… 版本号 + 最小化 / 最大化 / 关闭
  ├ 工具栏（透明）· · · · · · · · · · · · · · 1px 发丝线
  ├ 树（可关）· 1px 可拖竖线 · 详情列表 / 图标视图
  └ 视图栏 + 状态栏 · · · · · · · · · · · · · 1px 发丝线
```

- **顶栏只有一行**（2.4.0）。这一行原本是两行：第一行整条只写着 `Andzip (Professional) v… — 7-Zip …`
  一行字，菜单在第二行 —— 用户的话是「上面的文字去掉（第一行），第二行整体上移」。
  `TitleBar` 因此多收两个可选件：`leading`（左端替掉标题文字的那一块，主窗口放菜单栏）与
  `trailing`（挤在窗口按钮左边的那一小块，主窗口放版本号）。**对话框与进度窗口不传 `leading`**，
  走的还是"图标 + 标题文字"那一条 —— 它们本来就该说清自己是谁。
- **版本号从标题里挪到 `trailing`，没删**：截图要能自报身份（1.9.1 定的规矩）。
  `Window.Title` 照旧带着完整那一条（`Andzip (Professional) v… — 引擎…`），
  任务栏、Alt+Tab 与读屏器读的是它；屏幕上不再印一遍。
- 菜单栏搬进来之后，标题栏那条"空白处按下就开始拖窗口"的判断要把 `MenuItem` 也算进"不归我管"那一类，
  否则点「文件」变成拖窗口。
- **没有内部卡片**。标题栏、菜单、工具栏、内容、状态栏全在同一张表面上，
  彼此只用 1px 的 `Border.Hair` 分开（`Seam.Line()` / `Seam.Splitter()` 是唯一出处，
  别处不许现场写 `BorderThickness` 当分隔线）。1.8.0 起内部线比**面板外圈那圈边**（`Border.Subtle`）
  还淡一档 —— 用户对着旧版的意见是"左边的框体线太粗、不和谐"：量出来它只有 1px，
  粗的不是线，是它**顶天立地**把一整张表面读成了两个"框"。所以除了降色档，
  树与列表那根竖线还**上下各留 8px 不贴边**。
- **树那一栏不描边**：`SimpleTheme` 给 `TreeView` 的模板默认带一圈 `#888888`，
  必须显式 `_tree.BorderThickness = new Thickness(0)`（1.8.5；实测见第二节）。
  少这一行，屏幕上就是"左栏一个框 + 中间一根线"，与上面那条"没有内部卡片"直接矛盾 ——
  用户为这件事连报三次，前两次都改在了分栏线上。
- **树与列表之间那根线只有 1px，但命中区是 8px，而且必须是一枚控件**：`Seam.Splitter`
  以前把"看得见的细线"和"拖得动的透明条"叠在**一层宿主 Grid** 里 —— 那样它拖不动（1.8.9 用户反馈：
  「这条线应该是可以拖的，现在无法调整」）。两个条件缺一不可：
  ① **`GridSplitter` 只改它直接父级那枚 Grid 的列**，套一层宿主它就伸手去改那 8px 宽的宿主；
  ② **那 8px 命中带要有一层可命中的填充**（模板根 `Background = Transparent` 算填充，null 不算），
  否则整条带子只有中间那 1px 点得着。现在两层收进 `GridSplitter` 自己的模板，
  并且压上去是左右箭头（`SizeWestEast`）—— 一根会动的线要长得像能拖。
  以前那根是 4px 的 `Border.Strong` 粗杠，在没有卡片可分块的年代它是唯一能说"这里能拖"的办法，
  现在它把一整块表面劈成两半。
- **最大化时**圆角降到 `Radius.Xs`、透明边距收到 4px（见 4.4 第 4 条）。
- 首页与压缩包视图**同一套骨架**：打开包前后只有内容变了，窗口不跳样。

### 5.2 工具栏按钮

图标 40×40（线稿，见第六节）在上、文字在下（`Type.Body`，`Ink.900`），整体 `Radius.Lg`，
内距 14/8，最小宽 68。图标描边用 `Brand.600` —— 蓝在白色卡片上比在白底黑字上更聚焦，
这是 1.7.0 把整条蓝带撤掉之后品牌色剩下的主要落点。
悬停是 `Chrome.Lift()` 包出来的**那颗带阴影的圆角药丸**（状态见 3.1 末的三态表）。
**禁用态**除降透明度外，文字与图标同降为 `Ink.400`，不允许"图标淡了文字还亮着"；
禁用控件收不到指针事件，所以药丸在死按钮上根本不会出现。

同一颗药丸也用在这几处：底部视图栏的图标按钮（`ViewBar.Create` 负责包）、
标题栏的最小化 / 最大化 / 关闭（那里内缩 5px，格子仍是 46×40，浮起的是一颗 36×30 的小芯片）。

### 5.3 列表（详情视图）

- 表头：`Surface.Muted` 底、`Type.BodyStrong`、高 32、下边线 `Border.Subtle`；排序箭头用 `Brand.600`。
- 行高 28（图标 16 + 文字），**不做斑马纹** —— 试过，28px 行高下浅条纹只会让长表多一层噪声，
  而 SimpleTheme 的选中态本来就盖在条纹上；层级交给表头底色与行间距就够了。
- 选中行：`Brand.100` 底 + 左侧 3px `Brand.600` 标记条；文字仍 `Ink.900`（不反白 —— 列表是读东西的地方）。
- 悬停行：`Brand.50`。
- `..` 行文字用 `Ink.600`，与真实条目区分但不弱化到看不见。

### 5.4 树

### 5.6 对话框（通用规则）

- **窗口自己就是那张面板**（`Chrome.Chromeless()`：透明窗口 + 扩展客户端区 + 无系统按钮 +
  `Radius.Panel 22` + `Shadow.Floating`，外面 20px 透明边距，**不描边**）。
  **那一圈边距必须是空的**：窗口自己的底色由 `Chromeless()` 顺手设成透明（2.4.1 起）。
  在此之前它靠每扇窗口各自调一次 `WindowSurface()`，而安装向导与提示框两扇漏了 ——
  屏幕上就是"圆角面板外面一块方方的白板"，阴影等于画在白纸上，整套浮起的读法全丢。
  **判据是 alpha 不是颜色**：白底与透明在一张截图上都可能是 `#FFFFFF`，
  要量就得量 alpha（`CardLanguageTests.TheRingOutsideThePanelIsTransparentOnEveryWindow` 逐扇量），
  用眼睛看则要**把窗口开在后面有内容的地方**，开在白桌面前面看不出任何区别。
  九个对话框（提示 / 新建 / 口令 / 选择解压路径 / 重名 / 分卷大小 / 修复 / 进度 / **安装器**）全部如此 ——
  由 `CardLanguageTests` 逐个断言"根内容是 Border 且有阴影、圆角 ≥ 12"。
  标题栏是最右边**只有一个关闭钮**的那一条：对话框不该有最小化/最大化。
  对话框那一条**仍然写着标题文字**（2.4.0 把主窗口那一行换成菜单栏时，`leading` 只有主窗口传，
  对话框与进度窗口走的是默认那一条）—— 它们本来就该在顶上说自己是谁。
- 内边距 24，正文与按钮区之间 24，按钮右对齐、间距 10 → **12**。
- 主按钮（确定/开始/删除）：`Brand.600` 底白字 `Radius.Sm`；悬停 `Brand.500`；按下 `Brand.700`。
- 次按钮（取消/浏览）：白底 + `Border.Strong` 描边 + `Ink.900` 文字；悬停底 `Surface.Muted`。
- **危险动作**（永久删除）主按钮用 `Danger.600` 底白字，且按钮文字必须是动词（「删除」不是「确定」）。
- 输入框：高 30、`Radius.Sm`、描边 `Border.Strong`；获得焦点时描边 `Brand.600` + 1px 外圈 `Brand.100`
  （焦点环，见第八节）。**下拉框与输入框同一档**（1.9.0）：SimpleTheme 给 `ComboBox` 自带一圈
  `#888888`，比这档重两级，`Chrome.Picker` 显式换成 `Border.Strong` —— 同一张表单里两种描边
  就是用户说的"线太粗、不和谐"（1.8.5 那圈树描边同一族）。
- 错误/提示行（如 ZIP 口令的 ASCII 限制提示）：`Danger.600` 文字 + `Danger.50` 底 + `Radius.Sm`
  + 内距 8/12，左侧带 16px 感叹号图标。
- **随控件取值起落的说明行**（2.2.0，「新建压缩文件」的方法警告）：`Ink.Secondary` 文字 +
  `Type.Caption` 字号 + `TextWrapping.Wrap`，**不是**红底错误条 —— 用户没做错任何事，只是要知情。
  它挂在选中项下面而不是常驻：默认那几档（LZMA2 / LZMA / PPMd）不适用这句话，常驻就成了噪音。
  断言走 `VisualQuery.VisibleTexts`（只走真看得见的那一支），所以"代码里写了 `IsVisible = false`
  但祖先还藏着"这类假绿抓得到；两轮循环（五种扩展方法各点一次、六种标准方法各点一次）之外还比一次
  下拉内容与测试清单相等，表里新加一档而测试没跟上会当场红。
- **结果框可以给"下一步"当主按钮**（2.3.0，「测试未通过」那一屏）：坏 ZIP 的结果框是
  「尝试修复…」（`Brand.600` 主按钮）+「关闭」（幽灵按钮），不是「确定」+「取消」——
  用户刚看完坏成员名单，这一屏真正要回答的是"要不要现在修"。两条规矩：
  **修不了的格式（7z / tar…）就不给那颗按钮**（点了只会说"修不了"，比不摆更糟），
  以及文案**要认来路**（从测试过来的"结构完好"不能再说"数据有没有坏要用测试"）。
- **提示框的长文案必须折行**（1.8.6）：正文与图标是 `Grid` 的 `Auto,*` 两列。
  用横向 `StackPanel` 的话它给子元素**无限宽**，`TextWrapping.Wrap` 永不触发，
  长句子直接被窗口右边界裁掉（真机截图里那句"…都对得上，没"）。
  断言量的是宽度而不是"看不看得见"：正文测到 1116 > 窗口 460 就是红。
- **外圆角是做到了的**（1.7.0）：不是靠 DWM（`DWMWA_WINDOW_CORNER_PREFERENCE` 是 Win11 才有的属性，
  这台 Win10 用不了），而是靠透明窗口 + 自己画的那张圆角面板。
  用的是 `ExtendClientAreaToDecorationsHint` 而不是 `SystemDecorations=None` ——
  前者保留系统给的贴边缩放、Win+方向键分屏与任务栏让位，实测最大化正好铺满工作区。

### 5.7 进度窗口

同 5.6：内容包在卡片里。进度条高 8、`Radius.Pill`、`Brand.600` 填充、`Border.Subtle` 轨道；
百分比 `Type.BodyStrong` 与剩余时间同行（`Type.Caption`、`Ink.600`）。当前条目名一行截断 + ToolTip。

- **框上没有「取消」按钮**（1.9.2，用户提的）。取消只有两条路：**Esc**（受
  「常规 → 解压过程中允许按 Esc 取消」管，防的就是误按）与**右上角的叉号**。
  原来右下角那颗按钮被卡片的下边界切掉一半 —— 因为窗口高度写死成 168，而内容排不下。
  现在这颗框 `SizeToContent = Height`：**高度跟着内容走，不靠一个手写的像素数**，
  以后往里面加东西也不会再切到谁（`ScreenshotTests.ProgressWindowPaintsWithoutAnythingCutOff`
  量"进度条下沿到卡片下沿还剩多少"，不足下内距就红）。
- **叉号必须"取消这件事"，不是"把框藏起来"**：`Chrome.Chromeless` 因此多了一个可选的
  `onClose`，默认仍是 `Close()`，只有进度窗口把它换成 `Cancel`（取消令牌 + 关窗）。
  后台还在搬字节而窗口没了，用户读到的是"软件自己关了"，不是"我取消了"。

### 5.8 设置窗口（1.7.0 重做）

```
面板（一张表面，无内部卡片）
├ 自绘标题栏（40）
├ 左导航（宽 200）│ 1px 竖线 │ 内容：分组标题 + 行（左说明 / 右控件 / 灰字补充）
└ 页脚（透明，按钮右对齐）
```

- **导航选中态是"一块白色药丸"而不是颜色标记**：选中项 `Surface` 底 + 1px `Border.Subtle` +
  `Ink.900` 加粗，未选中透明 + `Ink.600`。以前是"淡蓝底 + 左侧 3px 蓝条"。
  这里给不了真阴影 —— `BoxShadow` 是 Border 的属性，导航项是 Button（规范 4.4 第 2 条），
  白底压在整块表面上已经有明度差，够用。
- **药丸画在 Content 里那颗自绘 `Border` 上，而且铺满整行**（1.8.7）。两件事都别商量：
  交给按钮模板画，`SimpleTheme` 会在 `:pressed` 上涂一整块 `#686868`，
  应用层的 `Background` 压不过它（浅底上一块脏灰，文字几乎读不出来）；
  而药丸只要留 margin，那层深灰就从缝里透出来，等于没修。
  按下那一档因此归 `Surface.Pressed`，三档状态现读现画（`IsPressed` / `IsPointerOver` / 选中）。
  **1.8.8 补：交给模板画的那一类控件（不是导航这种自绘药丸）也得单独挡 —— 见下面那条"每一颗按钮都要钉面皮"。**
- **导航条目之间不许留空隙**（1.8.7）：`StackPanel.Spacing` 那 4px 不属于任何按钮，
  手指在列表上移动必然划到它，划到就没反应 —— 用户不会描述成"4 像素点不到"，只会说"体验很不好"。
  `Spacing = 0`，行的呼吸感做进药丸自己的上下内距，整行都是命中区。
- **行式布局**：每一行是「左说明（可换行）+ 右控件」，补充说明在说明下面一行 `Type.Caption` `Ink.600`。
  行与行之间**不画分隔线**，靠 12px 间距分组。以前是"勾选框 + 后面跟一串字 + 一条独立灰字"，
  中英文一换行就断在不同位置；现在控件永远贴右，两种语言对齐在同一条竖线上。
- 页脚透明、按钮右对齐（`重置` 是次按钮、`确定` 是主按钮）。
- **一个设置键只归一页管**。落盘时机也统一：要么点「立即应用」就走，要么等「确定」，
  不许两页各摆一份控件去写同一个键 —— 两边都以为自己是真相，谁后落盘谁说了算
  （1.6.0 把「双击压缩包时」从常规页搬到解压页就是这个理由）。
- 导航**不放图标**。参考风格那一排是带图标的，但我们这九个页面没有对应的图形语言，
  拿通用图形凑只会变成"每页一个不相干的小图案"。宁可少一样，不要凑一样（见第七节）。
- **内容比窗口高就套 `ScrollViewer`，不撑窗口尺寸**（2.5.0 起这一条对**每一页**成立）：
  查看页加了「图标配色」整节（两块预览 + 五格颜色 + 一排按钮）之后比对话框高，
  而这一页从来不需要滚动 —— 结果是**底部两排按钮在屏幕外，且没有任何滚动条**。
  headless 断言"控件在不在、可不可用"，**不断言看不看得见**，所以这一处只有真机能抓到。
  判据：一页的根节点是 `ScrollViewer`（`VerticalScrollBarVisibility=Auto`，横向 `Disabled`），
  并且有一条用例"滚到底，最后一排按钮要落进视口"。

#### 5.8.1 图标配色这一节（2.5.0）

一张**算出来**的图标，边改边看。它给这套界面带来三个原来没有的控件形状：

- **色片行（预设 / 方向）**：一排 `34×24`（方向是 `34×26`）的小按钮，`Radius.Sm`，
  预设那一片的 `Background` 就是它代表的那条渐变 —— **色片本身就是内容**，所以它不需要旁边再写字。
  选中态是 `BorderThickness = 2`（未选中 0），与导航那一条同一族语言：**用描边表达"选中"，不用底色**。
  方向那一排是四个箭头字符（`↘ ↓ → ↙`）—— 方向不是文案，不进气泡语言包。
- **色片没有文字，所以必须给无障碍名**：`AutomationProperties.Name` 写成那三个十六进制
  （`#4AD9DC #2E9BF0 #2264E8`）。不写的话读屏念出来只是"按钮 按钮 按钮"，测试也没法按身份认领它。
- **颜色行 = 一块色 + 一个可打的框**：左 `30×24` 的 `Border` 是**现读现画**的色块
  （那一格里正在打的字认得就用它，认不得退回已存的那份），右边 `TextBox` 收十六进制。
  **认不得的输入不许把已存的颜色改掉** —— 用户清空重打的过程中预览不该闪成别的颜色，
  打完不合法就保留原值，而不是存进去一个 `#000000`。
- **预览卡片**：两种字形各一张 `64` 的图 + 底下 `Type.Caption` 的名字，整块包在一颗
  `PinFace()` 的按钮里（选中 2px `Ink.Primary` 描边）。**预览走的是与导出同一条渲染路**，
  不是另画一份示意图 —— 否则"预览对不上成品"这一族问题会在这里重演。
- **动作那一排只有颗「设为桌面图标」是主按钮**：导出与推导是次按钮，「恢复默认」也是次按钮。
  主按钮只给"这件事的结果会留在这台机器上"那一个 —— 它是这一节唯一改机器的动作。
- **状态行**（按钮下面一行 `Type.Caption`）：**照实说改了几处**。绿色版没有快捷方式、
  公共桌面写不进去、文件删不掉，三种落空各有说法，不许写死成一句"已设好"（见 §七）。
- 这一节所有色值都从 `Design` 令牌与用户挑的那套配色来，**界面代码里仍然零字面色值**
  （`DesignTokenTests` 扫源码把关；预览文字用的品牌上是 `Ink.OnBrand` 而不是 `Brushes.White`）。

### 5.9 开关（Toggle）与勾选框的分工

布尔项在设置页用**开关**，在文件关联页仍然用**勾选框** —— 这不是"新版式统一换成开关"：

| | 开关 | 勾选框 |
|---|---|---|
| 语义 | 程序的某个行为**开不开**（常驻状态） | 一批候选里**选哪几个**（多选清单） |
| 用在哪 | 设置页九个页面的 19 项 | 文件关联页的格式清单、新建压缩的选项、重名询问 |
| 为什么 | 位置（左/右）比一个勾更贴近"这是行为开关" | 几十个格式换成几十个开关只会更慢也更难看 |

实现上开关是 `ToggleButton` + 一颗自绘轨道：**行为交给控件**（Tab 聚焦、空格切换、读屏认得），
**视觉全部画在自己的 Border 上**（模板的 `:checked` setter 会盖掉控件自己的底色，见规范 §二最后一条）。
`ToggleSwitchTests` 三条分别钉：轨道真的是胶囊、滑块随状态换边、**空格键能切**。

### 5.10 弹出框（子菜单 / 右键菜单 / 下拉列表 / 提示气泡，1.8.0）

弹出来的东西与主面板是**同一套语言**：`Radius.Md` 圆角 + `Border.Subtle` 1px 描边 +
`Surface` 底 + `Shadow.Lift`。不许出现直角 —— 用户给的原话是"所有的弹出框和鼠标扫过的
置灰框都是圆润的且有阴影的，不要有直角"。

实现上有三条与直觉相反的实测（都在规范 §二 的表里）：

1. **弹窗的根是一枚 `Border`**，不是某个模板控件 —— 所以圆角与阴影是"打开的那一刻改属性"，
   不用重写 ControlTheme。调用点是 `SubmenuOpened` / `DropDownOpened`（`Chrome.RoundOnOpen`、
   `Chrome.Picker`），而且**要推迟一帧**：事件触发那一刻 `Popup.Child` 还没建出来。
2. **宿主 `ClipToBounds=true`，影子画不出宿主矩形**（把裁剪关掉也没用，宿主自己的矩形就是裁剪框）。
   所以 `Chrome.RoundPopups` 给那枚 Border 加留白让宿主变大 —— 但**只加右下两边**
   （`Margin = 0,0,12,12`），**并且完全不碰 `Popup` 的偏移**。
   "四周都留、再用 `Horizontal/VerticalOffset -= 12` 推回锚点"的做法是错的（1.8.0–1.8.2 就是这么写的）：
   实测 Avalonia 按**含 margin 的外框**定位弹窗，那一收等于把整块面板推到锚点身上，
   顶部菜单那一排被弹窗第一行盖住 —— 点上去既不关菜单、也传不到菜单项，
   用户看到的是"再点一次卡住"（开发记录第七节第 38 条）。
   光从上方来，左上本来就没有影，那两边不留白不损失观感。
   **这 12px 不是留白，是影子的活动空间**，删掉它圆角还在、影子没了。
3. **提示气泡没有 Border 可改**（模板里只有一枚 `ContentPresenter`），只能换模板
   （`Chrome.InstallBubbles` 用一条应用层 `Style` 设 `Template`）。
   气泡太小（实测 18×10 的脸），`Shadow.Lift` 在它外沿只读得出 1/255 的差值 ——
   所以那条测试钉的是"角是圆的"，不是"影子看得见"。

菜单项的高亮仍归 SimpleTheme（20% 品牌蓝），**只有顶部那一排**被换成轻微置灰（3.1 末）。
置灰的判据是"指针在上面 **或** 子菜单开着" —— 只看指针的话，鼠标一滑进子菜单，那一项就退回
模板的**直角**蓝，正是用户说的"扫过时圆角，点击变成直角"。
子菜单里的高亮没动：它在一块浮起来的白面板上，蓝色读得出"指针在这里"，
而且改它要动 `MenuItem` 的整套 ControlTheme，代价与收益不成比例（见 §七）。

### 5.11 安装 / 卸载向导（2.0.0，含 2.1.0 的「为所有用户安装」）

参考的是 Inno Setup 那一类：先看要做什么，再决定，再看它做。1.9.2 及以前是一整屏
（一个路径 + 两个开关 + 安装/卸载三颗按钮），点下去就动 —— 用户附了两张截图说"这个安装流程不对"。

| 页 | 给什么 | 页脚 |
|---|---|---|
| 欢迎 | 这次要装哪几样东西、这台机器装过没有 | 已装过时多一颗红色「卸载」；「取消」「下一步」 |
| 为哪位用户安装 | 两枚单选钮：仅为我自己（默认，不需要管理员）/ 为所有用户（要管理员，弹一次系统确认），加一段"两种装法各自独立"的说明 | 「上一步」「取消」「下一步」 |
| 选定安装位置 | 可改的路径框 + 「更改…」（系统文件夹框）、**所需空间 / 可用空间**、附加任务两个开关 | 「上一步」「取消」「安装」 |
| 正在安装 / 正在卸载 | 当前那一步说什么 + 一根真进度条 | **不给任何按钮** |
| 完成 | 只说真的做过的事（桌面那个有没有建、哪些扩展名被系统挡住、卸不掉的留到退出后删） | 「完成」（安装页才有「完成后运行」） |

- **标题跟着身份走**：带 `/uninstall` 进来时整扇窗的标题是「卸载 Andzip」，第一页是「确认卸载」。
  从控制面板那条卸载命令进来却先看见一个安装向导，是"没有 uninstall"那句抱怨的一半原因。
- **进行中关不掉**：`Closing` 里挡掉。复制进行到一半被终止会留下一个装了一半的目录，
  而这里没有回滚可做（只会复制一个文件，不会先备份旧的）。同理**不给"取消"** ——
  一颗当时按下去什么都不能停的按钮，比不放更让人犹豫（与 1.9.2 删掉进度框那颗按钮同一条理由）。
- **位置这一页的校验走在前面**：路径归一化 + 可写性探测（往最近的已存在祖先试写一个探针文件，
  **不创建目标目录**，否则一路改路径会在盘上留一堆空壳）。`Program Files` 那一类要管理员的位置
  在这一步就说明白，不等进度条走到一半才失败。
- **所需空间不估**：安装就是复制一个 exe，所以那个数就是它的实际字节；可用空间读不到时报
  「无法确定」而不是 0（一个假的"剩余 0"会让人以为盘满了）。
- **「为所有用户」那一页只多问一句，不多给一个假选项**（2.1.0）：默认选在「仅为我自己」，
  因为那一条不需要管理员；选另一个就把程序文件、快捷方式、卸载表、关联与右键动词
  整套换到机器级（`Program Files` / `%ProgramData%` / `HKLM`），**一处都不落在个人目录里**。
  要不要提权不靠"这个账户是不是管理员"这种猜测，靠那个位置现在的可写性实测；
  提权被拒就停在原地说明白，**不悄悄退回只给自己装**。
  提权成功则这一份立刻收窗 —— 两份实例同时在屏幕上，用户不知道哪个在装。
- **页与页之间窗口只长不缩**（2.4.0，`InstallerWindow.HoldHeight`）：这扇窗按内容自适应高度，
  而「正在安装」比「选定安装位置」矮两百多像素。页面一换窗口当场缩掉一截，
  用户点「安装」的那一下**松手**就落在窗口外面 —— 没收到松手的 Avalonia 以为左键还按着，
  等完成页把窗口撑回来，「完成」正好长在静止不动的指针底下，于是**向导自己按了「完成」**：
  完成页一闪而过、窗口自己关掉、还顺手把 Andzip 启动了。这条只有真机看得见
  （headless 点按钮走 `RaiseEvent`，没有"按下与松开落在不同尺寸上"这回事）。
  翻页前记下正文此刻的高度、作为之后每一页的下限，页脚就一直在同一格 ——
  参考软件那张向导也是所有页同一个高度，这不是为了修 bug 才立的规矩。
- **`uninstall.bat`：安装目录里要看得见一条出路**（2.4.0）。装完之后目录里是两件：
  `Andzip.exe` 与一个 202 字节的批处理，内容只有一行动作 `"%~dp0Andzip.exe" /uninstall`。
  **仍然不出 `uninstall.exe`** —— 真卸逻辑在 exe 里（它知道两种作用域、快捷方式、注册表，
  以及"删掉正在运行的自己"那件事），一个独立 exe 要么是那 20 MB 的第二份拷贝、
  也只是启动上面那一条的壳，而壳用批处理就是同一个东西。
  内容整个是 ASCII（`cmd` 按活动代码页解码这个文件，注释里塞中文会先变成一串 `?`），
  跟着安装目录一起收回。开始菜单里那一项「卸载 Andzip」与控制面板那条 `UninstallString`
  走的还是同一条路（快捷方式名来自语言包，装的时候把整条路径记进卸载表，
  换语言之后卸的仍是当初建的那一个）。
- **卸机器级那一份之前，问的是与装同一句**（2.4.0）：`Elevation.Needed` 那个判据
  （这个位置现在写不写得进去）2.1.0 只接在"装"那一路，于是从 `Program Files` 里双击
  `uninstall.bat` 进来是普通权限，跑到进度条上才失败，留下"点了卸载，那份却没动"。
  装要管理员而卸不要，在用户眼里不是设计，是"这个软件卸不干净"。
  提不到权就停在确认页说明白，**不悄悄只收当前用户那一处**。

## 六、图标规范

### 6.1 网格与笔画

| 项 | 规定 |
|---|---|
| 视框 | 24×24，所有图标共用 |
| 安全边距 | 四周各留 2（实际画在 20×20 内） |
| 描边宽度 | **1.5**（工具栏 40px 显示时等比放大，不额外加粗） |

| 视觉重量 | 同一组图标里，最大外接矩形对齐到 20×20；不允许一个图标撑满 24、另一个只有 14 |
| 颜色 | 工具栏白；内容区 `Ink.600`；选中态 `Brand.600`；危险动作 `Danger.600` |

### 6.2 图标清单

**几何路径的唯一真相是 `src/Andzip.App/Icons.cs`**，本表只记"这个图标要表达什么、
视觉上必须出现什么"。原因：把 20 条 path 抄进文档，代码改了文档不会跟着改 ——
那是两份真相，比没有文档更坏。

| 名称 | 用在哪 | 必须出现的视觉要素 |
|---|---|---|
| `Open` | 工具栏「打开」 | 文件夹轮廓 + 向右箭头（箭头不能压住文件夹上沿） |
| `Extract` | 工具栏「解压」 | 抽屉/容器 + 向下箭头穿过上沿 |
| `New` | 工具栏「新建」 | 压缩包主体 + **拉链齿**（这是本软件的身份图标，宁可牺牲一点可读性也要保留） |
| `Add` | 工具栏「添加」 | 文件轮廓 + 折角 + 加号（加号在文件外右下，不与折角打架） |
| `Delete` | 工具栏「删除」 | 文件轮廓 + 折角 + 减号 |
| `Test` | 工具栏「测试」 | 闪电（实心改描边，与其他线稿同重量） |
| `Scan` | 工具栏「扫描」 | 盾牌 + 对勾 |
| `View` | 工具栏「查看」 | 三行列表（方块 + 长线），行距均匀 |
| `Folder` | 树、列表、图标视图 | 带斜切标签页的文件夹，填充 + 描边 |
| `File` | 列表、图标视图 | 矩形 + 右上折角 |
| `Parent` | 列表 `..` 行 | 复用 `Folder`，靠文字与 `Ink.600` 区分，不另造图形 |
| `ListMode` | 视图栏「详情列表」 | 三条横线 + 左侧短标 |
| `IconMode` | 视图栏「图标视图」 | 2×2 方块 |
| `Locate` | 视图栏「打开压缩文件位置」 | 定位/图钉类：方框 + 右上角外指箭头 |
| `Info` | 对话框提示行 | 圆 + 小写 i |
| `Warning` | 错误/危险提示行 | 圆角三角 + 感叹号 |
| `Archive16` | 窗口/任务栏小尺寸 | 24 网格缩到 16 时描边降到 1，否则糊 |
| `Minimize` `Maximize` `Restore` `Close` | 自绘标题栏（1.7.0） | 系统符号，可辨识度优先于风格统一：描边 1.1、横平竖直。**它们不在 24 网格里**，见下面那段 |

> **窗口按钮是 16 分格 + `Stretch.None`，不是 24 分格 + 等比拉伸。**
> 最小化就是一条水平线，几何外接框**高度是 0** —— `Stretch.Uniform` 要按
> `min(宽/外接框宽, 高/外接框高)` 算缩放因子，除以 0 之后那条线在屏幕上缩成一个点。
> 属性全对、`Bounds` 正常、控件树里它就在那儿，只有画出来才看得见
> （守门断言：`TitleBarTests.MinimizeIsALineNotADot`）。

### 6.3 尺寸档位

`14`（列表行内）、`16`（树、菜单、提示行）、`20`（对话框标题）、`40`（工具栏）、`72`（图标视图大缩略图占位）。
非 14/16/20/40/72 的尺寸一律不许出现 —— 尺寸一多，视觉重量就散了。

### 6.4 程序图标（`assets/andzip.ico`，1.6.0 起）

上面 6.1–6.3 管的是**窗口里的线稿图标**；程序图标是另一件事：它出现在标题栏、任务栏、
资源管理器、右键菜单和「打开方式」列表里，那里没有 24 网格线稿的容身之地。

**1.8.0 起程序图标的真相是一张图，不是一段代码**：`assets/andzip.png`
（512×512、RGBA、四角 alpha=0，圆角渐变色块上写着 ZIP）。
1.6.0 那版"代码画的拉链方块"整套作废 —— 换图源不是因为它画得不好，而是因为
**图标与界面从此共用同一张位图**，不会再出现"桌面上一个图标、窗口里另一个图标"。

- **`.ico` 由 `assets/make_icon.py` 从那张 PNG 裁出来**：`python assets/make_icon.py`。
  脚本只做三件事 —— 按 alpha 外接框裁掉四周空白、按档位放回格子里、封成 ICO 容器。
  它**不再画任何几何**，所以规范这边也不该再记坐标。
- **小尺寸靠"占满"而不是"简化"**。≤32 那三档用贴边档（画面占格子 94%，大图 86%）：
  不裁的话 16px 上有效画面只剩 11px，图标在任务栏里又小又虚。
  大图自带的那圈软投影在 16px 上确实会糊 —— 但它就在 alpha 里，裁不掉，
  所以这里没有"小尺寸专用画法"这回事，别假装做了。
- **ICO 容器**：16/24/32 存 32 位无压缩 DIB，48/64/128/256 存 PNG，目录按面积从大到小排。
  小尺寸不用 PNG 条目是因为 Office/Outlook 这类老组件读 16px 时只认位图 —— 症状是
  "在某个程序里图标是一片空白"，而 shell 自己看不出问题。
- **透明通道是这一节的重点**：DIB 是 BGRA + 全 0 的 AND 掩码，四角 alpha=0。
  这条直接决定"正常安装"后桌面上那个图标是圆角的还是一块带白边的方砖。
  `AssetIconTests` 逐档读字节验四角，图源自己也单独查一遍 PNG 的 IHDR 颜色类型必须是 6。
- **界面里的三枚图标同源**：exe 上的（`<ApplicationIcon>`）、任务栏与 Alt+Tab 的
  （`Window.Icon = Assets.AppIcon`，由 `Chrome.WindowSurface` 统一发）、
  标题栏左上角那枚 16px（`Assets.AppArt`，内嵌的同一张 PNG）。
  内嵌是必须的 —— 单文件绿色版旁边没有 `assets/` 目录。
- **`Icons.AppMark` 只留作兜底**：万一内嵌资源读不出来，标题栏至少还有东西可画。
- **用户可以换掉这一枚**（2.5.0，规范 5.8.1）：出厂那张仍然内嵌在 exe 里，
  自定义那张落在 `%APPDATA%\Andzip\Andzip.ico`，`Assets` 在两者之间做一层
  （`AppIcon` / `AppArt` 先给自定义的，没有再给内嵌的），并广播一个 `IconChanged`
  让**已经开着的**每一扇窗口与标题栏那枚重画 —— 换图标不许要求重启。
  形状、构图、四档方向与"小尺寸占满"这些规矩**一条都不变**，用户挑的只有颜色与字形；
  四角 alpha=0 也一样，所以桌面上不会出现带白边的方砖。
- **验证**：`AssetIconTests` 解析 `.ico` 目录（七档齐全、小的是位图、大的是 PNG、大的排前面、
  小的四角真透明）；`InstallerTests` 读回桌面快捷方式的图标字段，确认它指向安装后的那个 exe。
  真机那一遍看的是 `contact_sheet()` 出的浅底 / 深底两行对照图与桌面截图。

## 七、不做的事（写清楚，别让人以后"顺手补上"）

| 不做什么 | 为什么 |
|---|---|
| Acrylic / Mica 背景模糊 | SimpleTheme 没有 backdrop blur；Avalonia 要做到得自绘透明窗口 + 系统材质 API，成本与收益完全不成比例 |
| 窗口内部的阴影 | `Border.BoxShadow` 实测画得出来（规范二），但只用在「整块面板浮在桌面上」这一层。内部再放带影子的卡片，就是被否掉的那版一屏四块白板；而模板控件（Button / TextBox）本来也没有这个属性 |
| 动画过渡主题切换 | 主题切换是整份重画（见 10.5），叠一层淡入要在切换期间同时存在两套调色板，收益是闪一下 |
| 布局动画（滑动、展开动画） | 工具类软件在进度中跳动会被读成卡顿；只做颜色/透明度过渡 |
| 自绘勾选框 / 单选框 / 滚动条 | 系统控件的可辨识度优先。**设置页的开关是例外**（规范 5.9）：那一项的语义是「某个行为开不开」，位置比一个勾更贴，而且它仍然建在 `ToggleButton` 上，键盘与读屏没丢 |
| 设置页导航项的图标 | 参考风格那一排是带图标的，但我们这九个页面没有对应的图形语言，拿通用图形凑只会变成「每页一个不相干的小图案」。宁可少一样，不要凑一样 |
| 图标用 emoji 或字体图标 | 字体图标依赖系统字体，绿色版在别的机器上会变豆腐块 |
| 「为所有用户安装」之外的一切机器级写入（系统服务、开机自启、`HKLM` 下别的键） | 2.1.0 开了机器级这一个口子，是因为"给这台电脑上的所有人都能用"是一个真实需求，而它只需要动 Andzip 自己那几处（`Software\Classes\Andzip.*`、自己的卸载表、自己的目录）。除此之外一处都不写机器级：那正是"装一个解压工具顺手改了系统"的来源（5.11） |
| 安装进行中的「取消」按钮 | 复制一个文件停不下来，也没有回滚可做（只会复制一个文件，不会先备份旧的），所以那颗按钮按下去什么都不能停；窗口在完成之前也关不掉（`Closing` 里挡）。半途而废留下的装了一半的目录，比一颗"点了没反应"的按钮糟得多（5.11） |
| 改 exe 自己的图标资源（"用户挑的图标直接写回 Andzip.exe"） | PE 的资源段在运行时改不了：正在跑的那个文件改不动，改别的副本又要管理员权限去动安装目录，还会破坏文件签名与绿色版"一个文件就是全部"的前提。所以自定义图标的形态是**旁边一个 .ico 文件，各处去指它**（6.4 / 5.8.1）—— 这不是绕路，是这台机器上唯一诚实的做法 |
| 「设为桌面图标」时顺手提权 | 公共桌面上那一个（机器级安装）在普通权限下写不进去，就**照实说那一个改不动**。为了界面上那句"已设好"去弹一次 UAC，是把"换个图标"偷偷升级成"改这台机器"（5.11 同一条判据） |

## 八、无障碍与状态

- **对比度**：正文与关键状态文字 ≥ 4.5:1（第三节已逐个标注）；`Ink.400` 只允许出现在禁用内容上。
- **焦点可见**：键盘焦点必须有 2px 环（`Brand.600` 内环 + `Brand.100` 外圈），
  且**不能只在悬停时出现**。Tab 走一遍主窗口：菜单 → 工具栏 → 树 → 列表 → 状态栏按钮。
- **命中区**：任何可点元素 ≥ 28×28（工具栏按钮 68×78，列表行 28，勾选框整行可点）。
- **不只靠颜色**：错误 = 红字 + 感叹号图标 + 文案里说清怎么办；排序 = 箭头 + 表头加粗。
- **文字不被裁**：所有可能变长的文字（按钮、状态栏、文件名）都要有 `TextTrimming` 或换行策略；
  中文/英文切换后按钮文案变长是常态（英文普遍比中文长 30-60%）。
- **每一句陈述都跟着状态重算**。界面上写出去的话只有义务**复述已经发生的事实**：
  安装器那句「已安装。桌面与开始菜单的快捷方式已创建」原本是写死的文案，
  而桌面那一枚 `.lnk` 因为目录解析失败根本没建（1.8.4；诊断见 `docs/开发记录.md` 第七节第 40 条）；
  同一屏上卸载按钮按磁盘状态消失了，「这台机器上已经装过」却还留在原处。
  现在两处都走同一次重算，做不到的那件事就不提它（`InstallOutcome.DesktopShortcut` 为这句而存在）。

## 十、深色主题（夜间模式，1.5.0）

### 10.1 三种偏好

`设置 → 查看 → 界面主题`：**跟随系统**（默认）/ **浅色** / **深色**。
存的是偏好（`theme_mode = system|light|dark`），生效的是两套调色板之一 ——
"跟随系统"不是一个第三种颜色，它必须被折算成浅或深（`ThemeMode.PrefersDark`，有真值表测试）。

默认选"跟随系统"而不是"浅色"：一台把系统设成深色的机器，装上一个刺眼的浅色窗口不是保守，是没跟上。

### 10.2 两套调色板怎么对应

**角色不变，数值重算。** 不是"把浅色取反"，也不是"深色版沿用同一批强调色"：

| 角色 | 规则 |
|---|---|
| 内容底 / 页脚 / 沉底 | 由白→深灰蓝（`#1F2328` / `#262B31` / `#1A1E22`），**不用纯黑**（见 §3.2 的光晕说明） |
| 正文 / 次要文字 | 由深→浅（`#E7EBF0` / `#A7B0BA`），比纯白低一档，避免"白字在深底上发飘" |
| 分隔线 / 描边 | 从"比白底深一点"变成"比深底亮一点" —— 层级方向跟着底色翻转，否则线上看不出边界 |
| 品牌蓝（**浅字的底**：工具栏带、主按钮） | **压深**（`#0F6CBD` → `#1B5E9E`）。提亮会把白字对比打到 AA 以下 |
| 品牌蓝（**深字的底**：选中行、信息条） | 压成深蓝（`#E1EEFB` → `#1E3A52`）。同一个色名，两种角色，两套数值 |
| 语义色 | 全部换成"粉彩化"的浅版本（错误 `#C42B1C` → `#F28B82`）：饱和的深红压在黑底上几乎读不出来 |
| 悬停/按下叠加 | 仍是半透明白（`12%` / `20%`）—— 在深色带上"加亮"仍是"浮起"的正确隐喻 |
| 文件夹图标 | 面 `#F7C948` → `#D9A61F`，边 `#D9A61F` → `#8A6100`：黄色在深底上要压暗才不刺眼，而描边要**更暗**才能守住轮廓 |

### 10.3 组件差异（只列与浅色不同的地方）

- **工具栏带**：`Brand.600` 深色值；带子下沿那条线用 `Brand.700`，深底下仍看得出边界。
- **列表/树选中行**：深蓝底 + 浅字 + 左侧 3px `Brand.400` 标记条（浅色下是 `Brand.600`）。
- **主按钮**：深色底上的实心蓝要更"闷"一点，白字对比反而更高（6.68:1）。
- **错误/确认框的圆形图标底**：`Danger.50` / `Brand.50` 的深色版本（是"染色的深底"，不是亮块）。
- **进度条**：轨道用 `Border.Subtle`（深色），填充 `Brand.600`；胶囊形状不变。
- **标题栏**：走 DWM 的 `DWMWA_USE_IMMERSIVE_DARK_MODE`（`Services/WindowTheme.cs`），
  属性设在 `Opened` 之后 —— 但**这台机器上实测没有效果**：`DwmSetWindowAttribute` 返回 `S_OK`，
  标题栏中点颜色前后都是 `rgb(248,248,247)`，再补一次最小化/恢复也不变。
  所以标题栏深浅**不算这一版交付的效果**，代码留着（Win11 上这是标准做法，本机无法验证），
  文档不许说"标题栏会跟着变深"。

### 10.4 深色下仍然由主题自己画的部件（如实说明）

实测（探 `SimpleTheme` 的资源键与像素）：它暴露 55 个资源键，**里面没有表面色**；
把 `RequestedThemeVariant` 设成 `Dark`，窗口角仍是 `#FFFFFF`，整幅画面的暗像素占比只从 0.3% 到 3.9%。
所以深浅主要来自我们自己的调色板，以下几处仍由 SimpleTheme 画，深色下会偏浅：

| 部件 | 现状（深色截图实测） | 为什么先这样 |
|---|---|---|
| 勾选框 / 单选钮的方框内部 | 一小块浅色方框，勾上是蓝色对勾 | 要改得重写 `ControlTheme` 模板；改动面大、收益是几像素 |
| 滚动条槽与滑块 | 浅灰（列表底部那条最明显） | 同上 |
| 菜单项自己的文字与高亮（弹出层**里面**那些行） | 行文字仍由主题给色 | 弹出层的**底**已经归我们画（1.8.0，规范 5.10），行是 `MenuItem` 模板的事 |
| ~~下拉列表的弹出项背景~~ | ~~浅色~~ | **1.8.0 已清**：弹窗根那枚 Border 的底色设成 `Surface`，深色下跟着变深（`HoverAndPopupTests.SubmenuFaceFollowsThePaletteIntoDark` 钉着） |
| ~~提示气泡（ToolTip）~~ | ~~浅色~~ | **1.8.0 已清**：换了模板（`Chrome.InstallBubbles`），底是 `Surface` |
| ~~标题栏~~ | ~~浅色~~ | **1.7.0 已清**：标题栏改成自绘的那一条，跟着调色板走 |

这是**明确记录的取舍**，不是漏了：夜间模式的主体（窗口、工具栏、列表、树、对话框、状态栏、按钮、文字、
弹出的菜单与下拉列表）已经全部翻深，剩下的是几个"小面积浅色块"。真要清掉，代价是给这几类控件各写一份
`ControlTheme`，而 SimpleTheme 的模板本来就没有视觉层次可言（这也是我们不用 FluentTheme 的原因）。
**如果哪天要全清，从这张表开始，别从"看起来不舒服"开始。**

### 10.5 切换的实现约束

- 控件的颜色是在**构造时**从 `Design` 取一次就固化到实例上的（本工程没有 XAML，也没有资源绑定）。
  所以换主题必须**重建**，不是"改属性"：外壳（窗口底色、菜单条、工具栏带）直接改那几处底色，
  内容区（首页 / 压缩包视图）整份重做。见 `MainWindow.ApplyTheme()`。
- 换主题不能把用户扔回首页：正看着包就重建那个包的视图，位置要保住。
- `Design.Use()` 在深浅没变化时**不触发事件** —— 否则设置页每次刷新都会把界面重建一遍，
  表现为"改一个勾选框，窗口闪一下"。
- "跟随系统"靠 `Application.ActualThemeVariantChanged` 重新折算。
  系统读数在启动时一定拿到；运行中系统换深浅能不能推事件，取决于 Avalonia 与系统版本 ——
  推不到时表现为"要重启才跟上"，这一条**没有真机验证过**。
